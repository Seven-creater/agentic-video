# GLM 小范围关键瞬间精剪

将一次性看视频后猜切点，改为缺项驱动的局部观察。GLM 决定需要补看什么、哪些可见变化重要、保留范围与变速；Codex 只抽帧、核验映射、执行剪辑与记录。安装 skill 不会切换 Codex 的主模型，也不会自动把此文件传给 GLM。

## 在本项目中运行

先读当前仓库的 `AGENTS.md`、`docs/REFERENCE_LIBRARY_SPEC.md`、`docs/GLM_MICROCLIP_E2E_AUDIT_20261007.md` 与 `docs/GLM_SLOT_MICROCLIP_V2_20261007.md`。完整段落使用 `microclip_v2`，把 `craft_knowledge/GLM_SLOT_MICROCLIP_V2.md` 固定快照实际加入 GLM 提示并记录 SHA。旧 `microclip` 的单组三锚点仅用于历史缓存，不用于保留完整 slot；旧快照和回复保持原样。本文件负责 Codex 的操作方式。

继续使用 Codex 会话中的官方视觉 MCP 与 `glm-5.3-flash`。不要把套餐 MCP 换成独立标准 API、ZCode 或其他提供方。密钥使用隐藏输入或环境变量。

使用现有任务目录。先运行 CPU-only prepare，检查原视频 SHA、输入时轴、旧请求状态及本轮阶段授权，再执行已授权的局部试验。不得通过新建任务或删除历史恢复预算。具体命令以 `python -m omni_story.library.microclip_v2 --help` 为准；不要把仅有 proposal 当成执行授权。基础设施恢复只处理已记录、未发出下一请求的 CPU 错误，单独绑定停止结果与历史，不能重写原结果或增加渲染。

首轮只验证一个既有 GLM 粗剪 slot，建议约 5–15 秒，不预设电影人物、剧情答案、峰值或参考秒点。局部效果通过后再考虑整片，不启动旧重构或生成路线。

## 标准观察顺序

1. **独立全段观察。** 提供带真实 PTS 的概览与物理去音轨的正常速度短片，先记录画面、文字和未知，不提供旧剧情或切点。
2. **核验表达目标。** 再核验旧模型 slot 的原文目标、进出状态及衔接。它们是可错的任务导航。GLM 生成有证据的保留义务，每项映射原字段；不以缩小目标绕过缺项。
3. **多事件加密。** GLM 按缺项在整个段落选择多个区域与事件。单个动作的局部精看只是其中一部分；必须同时检查表达所需的其它状态、结果或反应，不套固定镜头模板。
4. **边界确认。** 每个事件分别查看候选帧本体及真实连续邻帧。已知帧的直接比较是合法观察，不能为避免重复而去掉锚点。不同网格的抽样目标时间和 PNG 存储路径不代表帧身份改变；真实 PTS、源 SHA 和像素必须一致。阻塞性缺项不能标为确认。
5. **计划与实际源切片。** GLM 选择确认边界、速度、停留和必要观看时间，所有义务映射实际切片。独立观察每条真正选入的连续短片，再比较是否支持含义；全段描述不能替代短切片证据。
6. **实际输出。** 执行一次微剪，隐藏目标先观察实际输出的连续静音视频与真实 PTS 密帧，再对照目标检查含义、衔接和精炼。观察不足、文字依赖与质量失败分别报告，不能用计划解释补全。

模型动作必须符合本地类型约束，不执行模型生成的自由 shell 命令。输入视频、帧、PTS、代理映射、请求和响应全部绑定 SHA。引用源帧 ID；程序换算切点，模型不得用估计秒数替代未观察的边界。

## 进度与停止

- 每轮必须增加新的可用观察，或解决先前明确的缺项。相同问题、相同证据或相同边界的重复陈述不算进度，立即结束该试验并记录局限。
- 观察步骤是有限的局部流程，不设置新的任意全任务请求总上限，也不启动循环式重剪。已知格式错误最多一次修复；语义失败不能伪装成格式失败反复调用。
- 已提交请求先等其明确结果。结果不明的付费输入、媒体或观察 lineage 不得改名、重编码后重放。
- 发生鉴权、平台额度或传输失败时保留原记录。局部试验失败后不得自动扩展整片、换素材或新建一轮。

## 交付和解释

交付真实局部源片与实际输出、绝对视频路径、使用的帧与切点、前后时长、操作理由、调用与失败记录。分别说明技术有效、视觉表达、精炼效果和模型自评；模型自评不能称为陌生观众真值。字幕证据不等于无字幕也可懂；本地截帧不证明云端逐帧观看。

阅读仓库 `docs/GLM_MICROCLIP_SKILL_RUN_20261007.md` 的实际试验边界。首版仅确认一组动作入点／峰值／出点，容易把所有可剪边界局限在动作附近，从而丢失上下文、落地或反应。动作摘录不能标为整个 slot 的含义保留成功。后续完整段落流程需要由模型分别确认表达所需的上下文与结果边界。

很短的实际输出若盲读报告仅看到首帧、未识别动态变化或人物，则该盲读不足以支持动态质量通过。记录该回复和观察不足；下一版应为输出提供同样有真实 PTS 的密帧证据，再结合正常播放确认，不能直接靠计划解释补全。不要因此在现有已结束阶段自动追加模型请求。

加速和慢放必须改善实际可见信息。尾帧停留只延长该帧已经承载的信息，不能补出被删掉的结果。父片缺少关键结果时如实说明，不能声称精剪创造了缺失画面。
