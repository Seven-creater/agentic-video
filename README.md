# Omni 自主参考视频到成片

独立 Python 仓库：输入一条参考视频，由 Omni 自主理解、创作、管理资产、观看素材并决定剪辑。
程序执行 API 请求、来源校验和 FFmpeg 操作，不提供人工剧情答案，不替模型选题、选图或选片。

换新聊天窗口时先读 [HANDOFF.md](HANDOFF.md)：代码阅读顺序、真实运行状态、服务器模型及历史启动协议。

```text
参考视频：原声、原画、原文字
  → 内容与剪辑联合理解，同一份参考记录贯穿下游
  → 三个主题候选 → Omni 自主选题 → 整体框架与固定资产描述
  → 逐段剧本、独立审核、有限修订 → 画面盲读与主旨对照
  → 资产主图 → 素材起始画面 → H3 完整动作素材
  → Omni 观看真实素材 → 选择实际入出点、顺序、速度、效果与音乐
  → FFmpeg 渲染 → Omni 观看实际成片 → 最多一次重剪与候选选择
```

故事过程时长、生成素材时长和成片时长分开；实际素材生成后才决定切片。
身体差异允许但不是必选题材。主旨应相似，段落结构是软偏好，不强制原片秒点或镜头数。
当前新故事按纯画面可读来创作，不依赖新增字幕、对白或旁白。

## 快速运行

需要 Python 3.10+，并将 `ffmpeg`、`ffprobe`、`curl` 放到 PATH。
在进程环境中设置 `DASHSCOPE_API_KEY` 与 `MINIMAX_API_KEY`，不要把密钥写入代码或 Git。
运行时代码只使用 Python 标准库，不需要 GPU，不连接服务器，也不导入旧项目。

在仓库根目录运行：

```powershell
python -m omni_story --video "C:\path\to\reference.mp4" --unlimited-image-jobs
```

这是实际付费全链命令，不是预览。`--unlimited-image-jobs` 解除图片任务数量上限，
但不解除有限修订和视频只提交一次的规则；省略此参数时默认图片上限为 12。
参考视频当前必须小于 10 MB，不会自动压缩或静默更换输入。

默认输出在 `runs/video_<参考SHA前12位>/`。需要续跑时使用同一个 `--output`，
不要删除任务记录或新开目录绕过已经提交的任务。
已完成阶段可校验后复用；未知提交、已失败任务和未完成文本阶段不能保证自动恢复。

具体安装、凭据、预算、结果查找与安全续跑见 [运行说明](docs/RUNNING.md)。

## 当前模型分工

| 工作 | 代码默认模型／接口 |
| --- | --- |
| 理解、创作、图片／视频审核、剪辑决定 | 阿里云 `qwen3.8-omni-flash` |
| 人物／道具主图 | 阿里云 `qwen-image-3.0-pro` |
| 场景主图 | 阿里云 `wan2.7-image-pro` |
| 1–3 张参考图编辑 | 阿里云 `qwen-image-edit-plus-2025-12-15` |
| 4–9 张参考图融合 | 阿里云 `wan2.7-image-pro` |
| 视频素材 | `MiniMax-H3`，768P，4–15 秒，最多三路并发 |
| 裁剪、效果、音乐和渲染 | FFmpeg，执行 Omni 的结构化编辑表 |

图片与视频均使用已恢复的原 API，没有静默切换提供商。
本仓库没有直接安装或运行第三方编剧／剪辑 skill；研究方法被落实为本地通用提示词和工具。

## 代码组织

| 位置 | 职责 |
| --- | --- |
| `omni_story/__main__.py` | 单一命令行入口；默认运行整条链 |
| `omni_story/pipeline.py` | 参考理解、主题、整体规划、逐段创作和文本审阅 |
| `omni_story/reference.py` | 共同参考记录、编辑方法与来源绑定 |
| `omni_story/production.py` | 资产、真实素材、剪辑和成片审阅的自动衔接与缓存 |
| `omni_story/media_backends.py` | 阿里云生图／改图和 MiniMax H3；保存不可重复提交的任务身份 |
| `omni_story/editing.py` | 实测时长、区间校验、剪辑统计和 FFmpeg 渲染 |
| `omni_story/api.py` | Omni 请求传输；凭据不写入请求留档 |
| `omni_story/contract.py` | 剧本、资产、状态交接的程序校验 |
| `omni_story/*prompts.py` | 固定通用提示词及复用来源，不包含某条参考片的人工改编答案 |
| `tests/` | 纯本地测试；合成响应与真实 FFmpeg，不调用付费模型 |

实际函数控制流、决策所有权和产物对应见 [代码地图](docs/CODE_MAP.md)。

## 留档与失败规则

唯一创作输入是参考视频。API 凭据、保存目录和预算授权属于基础设施输入。
所有模型请求、原始响应、审核、任务 ID、来源 SHA 和失败均留档。
内容审核仍不理想时，Omni 可以选择现有最佳候选继续，但拒绝记录不会被改成通过。
缺失文件、无效区间、余额不足、认证失败或提交状态不明是执行故障，不编造输出，也不自动重扣费。

最终媒体路径以 `production/result.json` 的 `final_video` 为准，不固定指向某个旧版本。
状态为 `model_checked_final_video` 或 `video_candidate_with_limitations` 时才有对应的成片候选；
`blocked` 表示尚未完成。模型核查不是人工真值，`production_release_allowed` 始终为 false。
