## 结论

首要问题是流程目标与合法操作范围冲突：实现把“保留段落含义并精炼”变成了单动作定位，
再将这一动作的三个局部邻域设为全部合法剪辑边界。即使模型想保留开头、落地或后续反应，
也没有可用边界。GLM 的观察矛盾、时长判断与输出审核不足进一步放大了问题。

这次验证了真实动作定位、时间映射和变速执行，没有验证完整段落精剪。不能据此断言
GLM 完全不能剪，也不能把实现成功当成精剪质量成功。

## 1. 原段表达要求没有成为稳定约束

授权中保存旧 GLM slot 的 `intended_takeaway`、`entry_state`、`exit_state` 和衔接描述，
但 `microclip.py` 的规划没有将其传递或转成待核验的保留要求。流程只取时间范围，
最后的 `preserved_visible_meaning` 由模型自行填写。

旧 slot 将本段解释为身体被质疑、训练受挫而保持乐观；新计划将保留含义改成了蛇逼近、
缠绕、抛飞和脱离。旧描述本身可能有错误，不能当画面事实；但若精剪任务需要保留该段
表达，就应先独立核验，再将成立的要求作为后续编辑目标。

当前合约只要求 `preserved_visible_meaning` 为非空字符串，没有原目标覆盖或前后衔接检查。
因此一个明确承认丢失完整叙事的计划仍能通过技术校验并渲染。

代码：`omni_story/library/microclip.py:78`、`:182`；
`omni_story/library/microclip_contracts.py:77`。
证据：`artifacts/microclip_finecut_v1_001.json` 的 slot，
`artifacts/microclip_finecut_v1/model_plan.json` 的保留含义、省略内容及限制。

把模型自己生成、经画面核验的表达目标传给编辑阶段，并不等同于人工提供剧情答案。
独立事实观察仍应隐藏创作意图；事实成立后，编辑阶段需要知道正在保留什么。

## 2. 单分支搜索与单组锚点限制了可达解

补看只能严格缩小当前区间，不能按缺项返回其它必要事件。本轮路径为
0–15 → 6–9.033333 → 6.6–7.233333 秒。最剧烈的动作变化被找到后，没有第二条路径去确认
开头、落地或反应。

锚点接口只接受一组 start/peak/end。随后 `boundary_ids` 只包含三个锚点及其邻域新帧；
最终全部切点必须来自这个集合。概览看到的 0、3、9、12 秒帧不能作为合法边界。

模型在 `model_plan.json` 中直接写明，0–6.5 秒铺垫和 7.3–15 秒落地后果因边界范围而无法纳入。
这是一项可以从代码和实际记录证明的硬限制，增加调用数量或修改“请保留含义”的措辞不能消除它。

代码：`microclip.py:113`、`:131`、`:146`、`:160`、`:184`；
`microclip_contracts.py:70`。

边界必须经观察确认这一原则合理；问题是只确认了一个动作的边界，随后用它约束整个段落。
修正应扩展模型选定的必要事件和已确认边界，不能简单允许未观察的任意秒数。

## 3. 补看剔除了需要比较的锚点，ready 没有验证缺项

边界邻域使用 `exclude_frame_ids=tuple(catalog)`，因此之前看过的锚点本体和部分相邻帧
不在该次图像附件。三个邻域实际只有 4、5、4 张新帧。模型明确说无法直接比较提名锚点。

程序把新的帧 ID 和区间缩小当作进度，没有检查关键缺项是否真正解决。
`ready` 可以与“首次接触未确认”“落地未出现”等 `missing_information` 同时存在，
程序只检查 action 是否 ready。

出点回复甚至区分了两个标准：若要求落地，当前出点偏早；若只要求抛飞完成，则可接受。
系统没有稳定的段落表达要求来确定应采用哪个标准，于是局部动作完成替代了完整段落结果。

代码：`microclip.py:157`、`:168`、`:180`；`microclip_contracts.py:18`。
证据：`edge_observation_0.json`、`edge_observation_2.json`。

必要的锚点对照不应与无意义的重复请求混为一谈。未来补看应显示锚点本身及前后帧，
记录具体解决了什么；仍须遵守未知付费请求不重放和已知格式错误最多一次修复的规则。

## 4. 相互矛盾的观察没有先解决

候选锚点说已经接触，后续邻域又说尚未接触。这些都是可错的模型陈述。

记录被一起交给规划，没有建立哪些陈述被新证据替代、哪些仍未解决的状态。
涉及行动者、接触、行动结果的冲突应影响可用证据和计划，而不只是出现在 limitations 文本中。

证据：`motion_facts.json`、`anchors.json`、`edge_observation_0.json`；
代码：`microclip.py:103`、`:179`、`:195`。

保留每个事件的表达义务与原锚点记录，将边界决策拆为以下两种模型可选意图：
