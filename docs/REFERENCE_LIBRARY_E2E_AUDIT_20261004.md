## 实际成片能表达什么

| 输出时间 | 实际画面 | 表达能力与缺项 |
| --- | --- | --- |
| 0–9 秒 | 阿宝与师父交流，阿宝查看身体；原片字幕含身材否定，新增文字概括被轻视 | 有被否定的铺垫，但具体意思很依赖可见文字。没有清楚展示一项先前做不到的任务。 |
| 9–17 秒 | 前部主要是阿宝躺着与师父对话，约 15.5–16.5 秒翻身、起立 | 能支持坚持或不放弃；不能把整段描述成高强度爆发，不能独自证明能力已经反驳偏见。 |
| 17–27 秒 | 桃树下争夺食物、训练互动、追逐包子；包子仍在枝头等画面 | 有训练动作，但未选入这次行动的明确成功结果。新增“掌控每一个动作”比可见证据更强。 |
| 27–32 秒 | 阿宝平稳端着多碗面，与鹅互动 | 日常动作确实可见；它本身不证明训练造成了能力进步，也不等同于克服身体限制后的生活自理。 |
| 32–34 秒 | 群众与鹅，鹅发言；所选两秒没有阿宝 | 可作反应镜头，但认可对象和行动结果的连接不足。“成为传奇”主要由文字提示，不能由该群众镜头独自证明。 |

可以读出一般的“被否定、坚持、训练、获得认可”励志含义；更准确的
“身体或外貌偏见被可见能力反驳”证据不足。画面里有真正的动作素材，仍缺少清楚的行动—结果—反应关系。
字幕并非禁止事项：参考自身也有文字。问题在于文字声称了动作和结果，而实际精切没有充分呈现。

## 各阶段的断点

### 1. 参考理解：主旨大致正确，部分解释被当成目标事实

参考约 0–5 秒建立身体特征与偏见，随后迅速进入强烈的实战动作；约 17–22 秒用照片和文字补充不同能力。
18.5 秒实际可见用脚写字。核心是用能力表现反驳低估，而不仅是“坚持训练”的一般励志。
`reference_reading.json` 的“刻苦训练、不懈努力”包含对经历的解释，参考并未直接呈现长期训练过程。
它可以作为创作思路，但不应取代实际参考的能力证明关系。

`glm_044` 已写明 method_0 要求消极铺垫紧接爆发动作，method_1 允许静态照片或短生活片段。
因此不能仅因新片使用动态画面就判 method_1 失败；要核实它是否完成紧凑的信息补充及对应作用。

### 2. 检索与精看：找到有潜力的区域，但事实粒度和可靠性不够

原第二轮检索已提出“缺训练成功动作和师父反应”的需求，进入了相关连续窗口。
问题不在于没有搜索到任何有用区域，而在于宽事件、用途解释和真实子镜头没有充分分开。

- `window_306...` 的重看 `glm_049` 明确记录：这里只是重压下站起，没有击败师父，主旨偏向毅力。
  后续规划和审核没有保留这一限制。
- `window_287...` 的重看 `glm_048` 返回空 `editing_observations`，未提供该训练窗口的新剪法核查。
  空数组和没有报冲突不证明旧事件全部准确；其旧 `usable_ranges` 仍可被计划使用。
- `window_367...` 的原精看将局部 77–89 秒概括成“村民围着熊猫、熊猫接受欢呼”。
  这种宽描述无法保证任取末尾两秒都包含熊猫和完整的受礼关系。
- 原训练精看有细节错误：后段被描述成落在“高耸石柱”，实际抽查是地面／石坡边缘。
  已完成精看是一次有来源的模型观察，不是永久真值。

粗索引是稀疏观察，唯一精看总计 24 分钟，没有看完 277 分钟电影。本轮没有使用 FlashVID。
本次修订受原 16 窗口上限约束，只能重组已看区域；该边界正常生效，但不能让弱证据升级为成功。

### 3. 具体规划：把宽窗口的好动作套到选错的几秒

最明确的例子是 `glm_055` 的 `seg_3`：

- 窗口起点原片 3430 秒；计划选 3469–3479 秒，即局部 **39–49 秒**。
- 计划称其“空中高难度翻滚、训练爆发”；实际这段主要是早期争夺和追逐。
- 原精看把高难度翻滚记在局部 58–69 秒、抓取结果记在 72–74 秒。
  本次独立抽查确认局部 68.5 秒确有空中倒翻，72.5／74／78.5 秒可见站立、持筷及包子。
  这些更完整的行动与结果没有出现在当前选段中。此核查用于定位遗漏，不是人工提供新的 EDL。

`seg_5` 同样从局部 77–89 的宽事件中只取 87–89，却仍标注熊猫角色，并声称完成社会认可。
反应镜头可以不出现主角，但必须通过前后画面建立反应对象；当前仅靠角色字段和字幕没有完成这件事。

程序要求选段落在已看 `usable_ranges` 内、角色与某个事件相交。
这保证来源和范围合法，不保证“声明的动作／结果恰好发生在所选几秒”。
参见 `omni_story/library/contracts.py:260–272` 与 `:360–375`。

### 4. 字幕校验：有引用，但时间与含义仍可能不成立

`seg_2` 新增文字“面对强压／绝不放弃”显示在源时间 **2281–2285 秒**；
引用的 event8 发生在 **2287–2289 秒**。两者没有时间交叠，现有验证仍通过。

原因是 `contracts.py:305–318` 只把证据事件与整个选段比较，未映射到字幕实际显示区间。
字幕可以预示后续动作，但那应明确标作预示或概括，不能被当成同期动作证据。
当前还没有语义校验来证明“精准掌控／成为传奇”等文字被实际动作和结果支撑。

### 5. 渲染：按计划执行，但呈现未充分服务表达

没有发现 FFmpeg 将这些模型范围裁成另一组范围的证据：五个范围、顺序、速度和输出 provenance 对应一致。
完整解码和缓存 SHA 已验证。技术执行问题不能替代内容问题。

GLM 全部选择 `framing=fit`。原电影已有宽银幕留黑，放进 720×1280 竖屏后形成横向窄带，
人物与动作较小；渲染器正确执行了 fit，但规划没有对实际可读性、景别和画面占比作有效核查。
同时，前两段交流占 17/34 秒，参考所要求的迅速能力反转被延后。
故事时长和结构允许变化，缺陷是迁移方法的作用没有随这种变化被重新核验。

末尾静音是独立的音乐完整性问题，不作为画面内容不合格的原因。
用户明确参考只有 BGM；此前从未核验 ASR 推断参考含解说的已确认事实表述已撤回。

### 6. 成片盲读与对照审核：观察矛盾没有阻止 pass

- `glm_056` 没有收到剧本、slot 和参考说明，确实实施了盲读。
  但动作、原片字幕、新增文字和推断都进入同一 `observed_fact`，无法判断理解来自哪里。
- 它把 9–16 秒写为对话；`glm_057` 对同一区间改称高强度爆发训练。
- 对照审核输入包含整个计划和盲读（`revision.py:252–256`）。这造成锚定风险；
  实际结果更接近计划意图，而与它收到的盲读事实矛盾。不能仅据此证明模型内部原因，但数据流和错误一致。
- 盲读与对照审核都把鹅认成猪，审核又称鹅、猪的父亲身份一致，仍给人物连续性 pass。

`validate_blind_reading`、`validate_review` 和 `validate_method_review` 检查 JSON、状态、方法覆盖、
合法时间和非空证据，不核验动作真假，也没有对盲读与对照审核的矛盾设置门控。
本次只读执行实际记录的现有验证器，均通过，说明“结构通过”不能代替“语义成立”。

### 7. 比较与交付：错误审核被继承为最终选片理由

`glm_058` 的媒体输入是参考原视频，三版候选以盲读及审核文字提供。
它不是再次观看三条候选后的直接视觉比较；它继承了“9–16 秒爆发训练”的错误作为新版胜出理由。
`revision.py:283` 用所选 review 的三个 pass 字段计算最终状态，没有额外处理未解决的事实冲突。

最佳有效候选仍可交付，但必须区分媒体有效、文字评为通过、实际画面证据仍有缺项。

## 建议修复顺序

1. **先补精切事实核查。** GLM 提出源入出点后，对准确选中的短片段独立记录人物、行动、结果及反应对象；
   核查通过后再用于叙事和剪法判断。旧记录保留，新事实与冲突另存。
2. **让 slot 使用证据约束。** 每段记录观众需要理解什么、哪些实际秒点支持、缺少什么。
   结果缺失时由 GLM 补检索或改写组织，不能只加强字幕语气。
3. **修正证据时间与类型。** 字幕展示区间映射到源时间；区分同期说明、概括和预示。
   盲读区分动作事实、文字事实和推断，不禁止合理图文表达。
4. **让审核必须解决矛盾。** 先保存不带预设答案的成片事实表，再对照参考。
   对话／爆发、人物身份、行动结果的冲突未解决时不得 pass。
5. **比较有证据的候选。** 选择依赖经过核查的实际输出证据，保留 partial；画面可读性和音乐节奏分别评估。
