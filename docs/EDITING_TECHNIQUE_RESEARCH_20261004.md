# 参考剪法的理解、迁移与执行：文献和官方能力调研

核查日期：2026-10-04，Asia/Shanghai。本文是新调研及工程建议，不是已实现功能或新的模型实验。遵守 [任务约定](REFERENCE_LIBRARY_SPEC.md) 和 [本地运行规则](REFERENCE_LIBRARY_LOCAL_RUN.md)：固定参考决定主旨与剪法，素材证据可改变 slots，GLM 自主作创作决定；旧生成线和抖音发现线继续冻结。

建议保留当前 GLM-5.3-Flash 官方 MCP 路线，先补剪法知识、真实镜头时间线、候选接缝和执行能力，再评估是否需要训练专用模型。没有证据证明更换模型或安装一个 skill 就能解决全部剪辑问题。

## 1. 当前运行揭示了什么

依据 [首轮实测](REFERENCE_LIBRARY_FIRST_RUN_20261004.md)、现有提示和最终审核：

- 固定参考约 21.93 秒。GLM 的原始理解识别了约 5–6 秒附近的紧邻对比反转，以及约 17–21 秒的图文蒙太奇；这些是模型观看估计，尚无原生帧测量确认。
- 最终候选约 77.37 秒，主旨 partial、剪法 partial、人物连续性 pass。对比间隔过大，结尾未执行参考的图文蒙太奇，实际声画节奏未审听。
- 6 个 EDL 素材范围不等于 6 个镜头。每个连续电影范围内可能含原片已有切镜；应从实际媒体测量镜头，区分继承的切点和系统新建拼接切点。
- `reference_prompt` 已要求形式与作用，但 `fine_prompt` 主要记录角色和事件，`plan_prompt` 没有逐项剪法到镜头／接缝操作的绑定。渲染器支持裁切、恒定倍速、灰度、fit/crop 和四种音频模式，尚无新字幕、定格、J/L cut 或独立声桥时间线。
- 第二轮补看的 8 个窗口没有进入最终两版 EDL，不能声称补看改善了剪法。

上述观察只解释当前漏项，不能从一条参考推导 GLM 的普遍能力上限。字幕也不能代替当前任务要求的实际行动与结果证据。

Skill 提供知识和工作流程，MCP 提供工具连接，见 [官方扩展组件说明](https://docs.bigmodel.cn/cn/coding-plan/learning-resources/agentic-extension)。安装给外层 Codex 的 skill 不会自动进入内层 GLM 的 MCP 规划请求。后续必须把相关剪法条目、参考证据、工具能力和验收规则显式传给 GLM，仍由它选剧情、角色、源片段和编辑操作。

## 3. 最相关文献及可借机制

以下总结是原文支持的机制；组合成我们的系统是待验证设计。

| 原始来源 | 可借机制 | 证据边界 |
| --- | --- | --- |
| [VEU-Bench，CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Li_VEU-Bench_Towards_Comprehensive_Understanding_of_Video_Editing_CVPR_2025_paper.html) | 将景别、运动、切镜等分成识别、解释、作用判断；使用剪辑知识库及正例训练专用理解模型。 | 共 19 项任务；理解或问答成绩不等于实际成片能力，未评测当前 GLM。 |
| [Automatic Style Transfer for Non-Linear Video Editing，CVPR 2021 AICCW workshop](https://research.google/pubs/automatic-style-transfer-for-non-linear-video-editing/)／[方法正文](https://arxiv.org/html/2105.06988v1) | 提取参考镜头的构图、速度、亮度与时间风格，匹配库内素材并实际施加编辑。 | 精确原速度仍依赖用户标注；主要面向独立音轨、有限素材库，未证明同主旨迁移。是 workshop，不是 CVPR 主会。 |
| [ESA，2025 预印本](https://arxiv.org/html/2511.02505v1) | 从参考提取景别和相机运动的转换语法，学习候选镜头序列的风格评分。 | 实验参考和小素材库有限；景别／运动转换统计不能代替人物因果、蒙太奇含义或声音关系。 |
| [Learning To Cut by Watching Movies，ICCV 2021](https://openaccess.thecvf.com/content/ICCV2021/html/Pardo_Learning_To_Cut_by_Watching_Movies_ICCV_2021_paper.html) | 学习真实相邻镜头的声画模式，排序候选切点及接缝。 | 局部剪切合理性不能证明整条影片表达参考主旨；本项目尚未部署该模型。 |
| [DIRECT，2026 预印本](https://arxiv.org/html/2604.04875v1) | 段落意图转为语义查询、剪辑优先级和节奏要求；受约束镜头搜索，失败后修改查询。 | 输入为文字指令、音乐和素材，不是异源参考联合迁移；具体查询幻觉、风格化画面的特征域差仍存在。 |
| [BEAT，2026 预印本](https://arxiv.org/abs/2605.27067) | 音乐能量与画面动态做弹性对齐，允许一个镜头跨多个小节。 | 主要研究预告片；不能简化成每拍必切，学习式对齐器及动画泛化未在本项目验证。 |
| [CutCraft / Beyond Coherence，2026-09 预印本](https://arxiv.org/html/2609.08275v1)／[作者代码](https://github.com/AlibabaResearch/cut-craft-bench) | 明确镜头和接缝的编辑规格；渲染后对齐实际镜头，分别检查蒙太奇、转场和声画错位，再定位修复。 | 研究约 15 秒合成多镜片；不能直接外推长电影检索。可借表示和检查方式，不必搬入完整专家服务。 |
| [VEBench，2026 原文](https://arxiv.org/html/2605.03276v2) | 将剪法识别和候选片选择／定位分别诊断。 | 操作模拟仍不是端到端成片；音频依赖手法必须有真实声音证据。 |
| [Timeline-Bench，2026-09-28 预印本、审稿中](https://arxiv.org/html/2609.35143v1) | 评价完整交付，用专业编辑盲评校准质量，区分格式合格与剪辑工艺。 | 其参考成片只用于评估，不给 agent；任务设置不同。可借盲评和故障对照，不能拿成绩预测本项目成功率。 |

这些研究共同支持：一般语义理解、人物连贯、名词识别和可播放都不足以证明剪法迁移；需要落实到实际相邻镜头、时间和声音。本文不将扩散模型的画面重绘／外观风格迁移视为我们的素材重剪方案。

## 4. 如何让 GLM 学到并运用剪法

这里的首阶段“学习”指检索知识、观看参考、调用工具与累积可验证案例，不代表云端模型参数被永久训练或自动更新。

### 4.1 通用知识与本次参考分别保存

每个通用剪法条目应有：定义、正例、容易混淆的反例、素材前提、可执行操作、观察方法、失败条件。知识来自可靠教材／论文和已核验例子，不编造当前电影素材。

参考分析再绑定当前视频中真正存在的实例：

| 信息 | 要求 |
| --- | --- |
| 形式 | 哪些画面、文字或声音，怎样排列或错位；名称不是证据。 |
| 作用 | 希望观众理解什么，改变哪些信息、预期或情绪。 |
| 参考证据 | 原件 SHA、镜头／接缝 ID、原时间；区分测量与模型估计。 |
| 素材前提 | 所需互补事件、动作阶段、角色状态、景别、运动及声音。 |
| 可改变条件 | 允许人物、事件、slot 数量及具体时长变化；主旨不能被弱化。 |
| 实施与核查 | 实际源片段、输出位置、操作、检查结果及缺项。 |

参照 VEU-Bench 的思路，要求 GLM 先指出具体模式，再解释作用；对同一接缝提供可能的其他解释，避免看到快动作就自动命名为动作匹配。

### 4.2 为参考和候选建立真实镜头／声音时间线

可先用 [PySceneDetect 官方检测器](https://www.scenedetect.com/docs/latest/api/detectors.html) 提出硬切、渐隐等边界，再由局部观察确认。保留检测分数和未确认状态，动画闪光、爆炸与高速运动可能误报。短参考不能直接沿用较长的最小镜头长度设置，否则快切会被合并。

全库可以做廉价切点目录，不要求 GLM 全片逐镜描述。语义精看仍由参考需求驱动。每个已选长范围展开内部切点，以真实镜头关系规划，继续允许保留有用的连续动作组。

音频另保存有效 ASR、起音／拍点候选、能量与静音。可参考 [librosa beat_track](https://librosa.org/doc/main/api/generated/librosa.beat.beat_track.html)，但电影混音中的爆炸、对白和响度峰值不等于音乐拍点；置信不足要标未知。测量不能代替声音语义和实际听感。

### 4.3 从“找相关片段”升级为“找能一起表达的镜头组”

让 GLM 同时提出内容需求与接续需求：单镜要证明什么，相邻镜头之间要建立什么关系。工具返回候选、来源和可用接缝，GLM 决定比较和选择。

例如当前模型提出的紧邻对比，应检索能形成意义反差的一组真实镜头，而非独立选两个“励志”片段；图文蒙太奇需要一组真实事件证据和可读的呈现条件。这里是方法要求，不由 Codex 指定电影事件、人物或时间切片。

可借 DIRECT 的受约束搜索和 ESA 的景别／运动语法，在有限候选中比较多个组合。保留跨镜角色状态、事件因果与上下文，不把单镜相似度求和当作完整故事评价。素材缺项时补看或改 slots，不能改参考目标。

新补看结果必须进入显式候选比较；若未使用，应记录是身份、动作、主旨、接续、重复还是预算条件不合适，避免再次出现“多看了却没有影响规划”的断层。

### 4.4 先支持参考需要的操作，再讨论广泛手法

当前优先补真实镜头级选择、相邻对比，以及定格／文字叠加和可读时长，后者仅用于实现模型已观察到的参考形式。GLM 选择冻结帧、文字及时间，所有文字有真实证据；不能用标题补造缺失的行动与结果。

每个编辑方法必须对应程序确实支持的操作。先有能力表和结构校验，再让 GLM 输出镜头组、接缝、速度、构图、图文和音频轨道；计划声明的方法未执行时保留缺项，不降格改称已实现。

J/L cut 等声桥需要独立画面／音频入出点、输出位置、音量包络和已观察的合法余量，当前尚未实现。可参考 [FFmpeg 官方滤镜](https://ffmpeg.org/ffmpeg-filters.html) 的 `atrim`、`asetpts`、`afade`、`acrossfade`；滤镜成功只证明执行，不能证明台词归属与声音自然。

### 4.5 边界附近精看，实际成片验证

连续窗口确认人物、事件与结果；候选切点附近再提取短连续片段或密集原生帧，确认动作相位、视线、位置和结果没有被截断。首个工程候选可检查约 ±0.5–1 秒的局部，具体范围由问题与素材决定，不作为通用最佳常数。

12 fps 代理每帧约 83 ms，且 MCP 内部采样未知；不能凭整体描述承诺帧级准确。源 SHA、原 PTS、代理映射和输出帧时间必须绑定，最后在原件解码时间轴上裁切。

成片重新测量实际镜头，并把剪法逐项映射到输出证据。分别判断形式、表达作用和声音条件；DINO 视觉距离只能提供差异信号，光流相似只能提供运动信号，均不是语义反转或正确动作接续的真值。

反馈应定位到实际镜头／边界并给出修复需求，例如缺证据、接续动作不成立、结果停留不足、文字不清或声音截断。GLM 决定再检索、换镜、改 slots 或移动切点；程序不人工改答案。

## 5. 如何证明“熟练运用”，并控制成本

建议在冻结协议后做等预算对照：当前基线；加知识与参考证据；再加镜头级检索／操作；最后加局部成片反馈。多条异源参考分别测试，不从单次补审或解释更完整推出质量提升。

至少分开评估：

1. 主旨：隐藏 slot、脚本和电影简介，陌生观众是否从画面看懂所需关系、行动与结果。
2. 剪法：参考确实存在的形式和作用是否在实际输出中出现，证据在哪些镜头和边界。
3. 连续性与声音：身份／状态、动作结果、对白完整、音画关系；未审听项保持待核验。
4. 成本：首次切点建库、本次检索观察、局部重看、请求及渲染分别记录；重复测量与已知结果复用。

人评用于研究验收，不参与运行时编剧或选片。GLM 自评可提供反馈，不能作为观众真值；评分知识库也不能直接提示盲读答案。

优先使用现有 CPU FFmpeg、切点检测、音频测量和当前官方 GLM 会话。ESA、BEAT、CutCraft 中的训练模块及专家服务先借设计，是否部署由后续等预算收益决定；这轮没有必要先租 GPU 服务器。

“剪法 skill”值得自建为薄知识层：相关条目按需进入内层 GLM 上下文，携带真实工具能力与检查要求。成功／失败案例带 SHA、操作及成片证据存档，不能将一次模型自评自动晋升为通用正确示范。以后若考虑专用模型微调，需要独立训练／测试划分和实际渲染评价，不能宣称写好提示就完成了模型训练。
