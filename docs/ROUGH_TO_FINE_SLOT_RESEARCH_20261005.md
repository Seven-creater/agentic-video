## 核实的主来源与可借用机制

- **Micro-Edits，作者项目列为UIST 2026。** 从已有粗剪出发，区分调时间的 rhythm edits 与引导注意的 view edits，包括切点调整、人物焦点、动作切和反应镜头。该研究包含音画同步条件和交互工具；不能直接当作静音动画的全自动 GLM 实验。它支持先保留粗剪内容，再调整局部时机与注意的方向。[作者项目与论文入口](https://microedits.github.io/)
- **DIRECT，2026预印本。** 将全局结构、段落编辑意图与底层搜索分层，局部意图控制语义查询、剪法优先项和节奏；镜头内部滑窗寻找切点并比较多个候选。采用离线视觉特征与搜索，不是仅给通用模型一段提示。适合借鉴分层和候选比较；本项目尚未复现其完整算法。[原论文](https://arxiv.org/html/2604.04875v1)
- **Computational Video Editing for Dialogue-Driven Scenes，SIGGRAPH 2017。** 将剪辑惯例写成可组合的规则，并结合镜头与内容标签选择序列。输入为剧本、多机位对白素材，原HMM不能原样用于本任务；可借鉴把手法组织成有条件的决策卡。[作者项目](https://graphics.stanford.edu/papers/roughcut/)
- **Write-A-Video，ACM TOG 2019。** 联合处理候选镜头、切换和段落偏好，而非只取相关长片段。其默认镜头时长可调整，不是我们的硬阈值。[原论文](https://cg.cs.tsinghua.edu.cn/papers/TOG-2019-Write-a-Video.pdf)
- **Learning to Cut by Watching Movies，ICCV 2021。** 从已剪影片学习真实／人工切换的区别，给候选切点合理性排序。可作为以后底层切点辅助方向；该排序不证明主题或行动结果，当前没有安装或训练它。[CVF原论文](https://openaccess.thecvf.com/content/ICCV2021/html/Pardo_Learning_To_Cut_by_Watching_Movies_ICCV_2021_paper.html)
- **Cutting与Armstrong，2016。** 表情识别与电影分析说明主体大小、杂乱程度与认读时间有关；没有“封号必须几秒”的通用结论。适合据此提出按实际画面检查重要人物曝光的规则。[期刊原文](https://link.springer.com/article/10.3758/s13414-015-1003-5)

Blackmagic官方训练也明确区分粗剪组装与后续trim、match frame、replace shots等精修；Adobe时间重映射文档提供一镜内部变速和过渡的执行方式。这些来源是编辑知识／工具方法，不是GLM叙事能力的验证。[Blackmagic训练](https://www.blackmagicdesign.com/products/davinciresolve/training)、[Adobe时间重映射](https://helpx.adobe.com/premiere/desktop/edit-projects/change-clip-speed/change-clip-speed-and-duration-using-time-remapping.html)

## 应组织成什么剪辑知识

以下表格是面向本项目的组合设计，不是某篇论文现成的完整算法。

| 手法 | 适用目的与条件 | 需要避免的失败 |
|---|---|---|
| 省略剪辑／时间压缩蒙太奇 | 用若干不连续的关键状态、行动和结果代替等待与重复过程 | 删掉唯一的结果或衔接，靠字幕补成发生过的事件 |
| 晚入早出 | 去掉已经能推断的准备和动作结束后的空余时间 | 过晚进入而不知谁对谁行动；过早退出而结果消失 |
| 动作中切换 | 动作方向、阶段和主体关系衔接，让注意连续 | 拼接无关动作，形成重复动作或空间方向冲突 |
| 姿态／构图匹配 | 连接有意义的形态、人物位置或运动相似性 | 画面很像但故事关系错误；相似性不证明因果 |
| 反应镜头与结果停留 | 让观众看出受影响者、结果、认可或情绪变化 | 从别的事件借反应而制造不存在的关系 |
| 局部慢放 | 关键动作本来存在，但太快难以辨认；需要突出姿态或转折 | 整段慢放变得拖沓；把缺失动作当作可用速度修复 |
| 过程加速／快慢对比 | 保留必要连续过程但压缩非关键时间，突出关键区间 | 加速唯一的身份指认或结果；误称多个恒速段为平滑速度坡道 |
| 定格／延长稳定形态 | 真实画面已经清楚表达身份、姿态或结果 | 冻结错误人物、遮挡或动作中途；停留不能补出不存在的结果 |

动作的高光不必是运动量最大的帧。形态高光可能是稳定姿态、可读表情或两人的位置关系。GLM应同时识别事件价值、形态辨识和上下文关系；峰值本身不能统一代替完整事件证据。

每张卡应包含：**表达目的 → 可观察条件 → 适用手法 → 可执行参数 → 禁用条件 → 渲染后比较问题**。
真实电影入出点与速度仍由GLM选择，Codex不预填本片关键帧或替代剪辑表。

## 推荐的后续结构

1. **固定可回退的粗剪。** 保存已有媒体、源入出点、slot用途、相邻段关系和用户接受记录。未来自动粗剪的门只看内容与呼应；34秒或更长本身不构成失败。时长与资源限制是两件事。
2. **先做局部事实，再做局部决策。** 每次只给当前slot的实际视频、对应原片与必要邻近上下文。独立事实阶段不提供期待动作答案；定位起始状态、关键形态、动作变化、实际结果与身份关系，区分可见事实和推断。保持源／粗剪／候选三条时间映射。
3. **按表达义务生成少量不同候选。** 比较原速删冗余、多个关键瞬间组接、局部慢放／快慢对比等真正不同的方案。2–3个是待验证工程选择；GLM可以判定某段不需要变速。第4段允许扩展，不能全片统一缩短百分比。
4. **把候选放回上下文观看。** 每段都带上一段结尾与下一段开头核验身份、状态、动作方向和问题／回应关系。保留少量备选后组合选择，不能把每段单独最漂亮的版本机械拼成整片。
5. **审核实际新视频。** 隐藏目标解释静音盲读，再比较粗剪表达是否保住、关键关系能否认清、冗余是否减少、手法是否实际执行。文本证据、画面事实、主旨解释分开。音乐节奏另做，不以卡点牺牲读懂内容。
6. **局部失败局部返回。** 只有一个slot看不懂就先修那一段；整片身份或呼应破坏才返回全局。相同方案和相同错误循环不计进展。已知格式失败最多一次修复，未知付费请求不重放。

粗剪通过后固定的是观众应理解的内容与段落关系；镜头长短、数量、段落边界和素材微调可以变化。若具体动作在独立原片事实中不成立，不能硬保错误文字；应保留用户认可的表达目标，并报告该实现仍有缺项。

## skill与现有工程的差距

智谱组织的Synapse仓库收录了`ffmpeg-video-editor`，正文主要将自然语言转成FFmpeg裁切、变速、格式转换等命令；来源元数据指向ClawHub。不能称为智谱已经验证的叙事精剪skill，也不能用它替代选关键瞬间和成片审看。[源码](https://github.com/zai-org/Synapse/blob/main/.setup/skills/clawhub/skills/ffmpeg-video-editor/SKILL.md)、[来源元数据](https://raw.githubusercontent.com/zai-org/Synapse/main/.setup/skills/clawhub/skills/ffmpeg-video-editor/.clawhub/origin.json)

本项目已有`LOCAL_TRIM.md`、`ACTIVE_FINE_CUT.md`等知识卡及局部裁切接口，但此前未形成用户认可的精剪质量结果。这次分别以实际render_0和render_3为父级，避免再用巨大全库上下文重新生成长草稿。项目知识卡必须真正进入每次GLM调用的输入；仅安装到Codex技能目录不会自动教授另一个模型。

当前渲染支持不连续片段、每段0.5–2倍恒速和真实末帧保持。平滑速度坡道、任意关键帧冻结、主体跟踪放大及高质量插帧尚不能从这些能力推导为已实现。前期可以用已有能力验证逐段决策；更复杂手法须在执行器实现、媒体验证后开放给模型。
