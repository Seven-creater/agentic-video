# 参考驱动视频剪辑系统：任务与评测协议 v1

系统的任务是：理解参考视频的表达意图，从固定素材库检索可用画面，联合规划镜头与声音，生成成片并提供来源和质量记录。热点捕获是上游入口；核心剪辑实验使用冻结的参考文件，避免热榜变化和网络故障改变两个方法的输入。

目前两条交付视频属于**开发案例**，第二条经过研发人员介入修复。它们证明链路可运行，不能作为未见样本，也不能据此报告“100% 自动产出”。本协议及运行工具准备好了，不代表新的批量实验已完成。

## 输入与输出

| 项目 | 冻结内容 |
| --- | --- |
| 参考输入 | 参考视频的实际文件、SHA-256、主题 ID；一个主题一个参考 |
| 素材输入 | 固定版本素材库、库清单或索引文件及 SHA-256、原片目录和视觉库目录 |
| 输出规格 | 当前实现为 1280×720、30 fps，允许的时长区间在实验前固定 |
| 执行预算 | 全批共享台账操作数上限、每次运行台账操作数上限、全批请求截止时间；计划费用额度另列 |
| 成功输出 | MP4、剪辑计划、素材来源和时间区间、完整调用收据、外部评测结果 |
| 其他输出 | 素材不足、候选未达标、运行失败、未决、预算停止等真实状态及原因和成本 |

本版硬守护共享台账操作数、每次运行台账操作数和截止后不再发起新请求；已在途请求保留结果，不承诺截止秒钟强杀服务端。`max_cost_cny=0` 禁止启动付费实验；非零执行还必须匹配本轮已核实的100元授权费用配置（见文末），缺失时拒绝启动。费用包络不等于提供方账户级硬扣费限额或已结算账单。`core_default_revision_policy` 仅描述核心既有修订策略，本版没有独立的 `max_revision_rounds` 硬守护，因此不接受该字段冒充已实现的控制。

系统必须允许回答“现有素材不足以完成此参考”。不适配样本仍留在测试集和产出率分母中，不能为了提高成功率逐个替换。

## 冻结测试集与两组方法

目标是 **20 个不同主题、不同参考 SHA-256 的 heldout 案例**。建议在运行前按对白/情节、动作反差、音乐节奏、生活/非动作主题各选约 5 个，并记下选样规则。不能看完系统结果再决定纳入哪些案例。

开发参考在 `development_references` 中预先声明主题和文件哈希；`cases[*].split` 明确标为 `development` 或 `heldout`，顶层 `split` 仅作为默认。已用于调试、选参或修改提示词的参考进入开发集。对测试案例临时手工选片必须记录人工干预，该次不能计入自动合格产出。运行中源码变化单列`protocol_deviation`并保守排除自动合格；仅凭全局版本变化不能断言每条视频都被人工编辑，逐案例人工干预无法确认时保留未知。

| method | 本协议定义 |
| --- | --- |
| `baseline_single_pass` | 使用同样的参考理解和素材检索，生成一次粗剪计划并进入真实配音与交付；不运行 finecut。仍包含必要的配音时长处理、真实声画和最终画面审核，不表示只调用一次 LLM。 |
| `full` | 相同输入与资源上限，执行完整粗剪、精剪、真实声画/最终画面审核及有限修订；预算内自动修订属于系统行为。 |

两组共用素材库版本、输出要求、模型版本和每次运行调用上限，记录实际耗用。全批另有共享调用上限和请求截止时间，可能使后续任务停止；未完成任务留在分母。完整系统的额外计算要在耗时和成本中体现，不能只比较质量。已有检索缓存若复用，应两组都可使用并如实披露；测试结果和评测答案不能作为另一组的输入。

`planned_runs` 在首次执行前冻结全部 case×method 组合。稳定运行 ID 为 `experiment_id/case_id/method_id`，与输出文件夹无关。每条结果都绑定源 manifest 的原始文件 SHA-256；禁止换目录重新执行 uncertain/submitted 调用、擦除失败记录、只留下成功重跑。已明确失败的恢复也要保留旧收据、累计预算与介入记录。

## 评测：技术门槛与独立质量判断

技术完成仅证明：实际文件存在且完整解码，分辨率、帧率、时长符合冻结规格，并存在可解码音轨。实际可听、非静音、没有明显截断，以及素材来源与语义是否有证据支持，须由声画审核、来源记录或人工复核分别证明；`technical_complete` 不是这些要求的全部证明。未决调用不得冒充成功，启动器退出码和“已写出 MP4”也不足以证明交付。

质量评测对象是**最终含字幕的真实成片和参考**，由支持实际声画输入的独立多模态评测者完成。生产内部 GLM/Qwen 审核用于改片，不能直接拿来当外部实验得分。评测者不看系统名称、方法名、计划中“应该出现”的内容或制作过程中的自评。A/B 展示顺序随机，比较时交换顺序复核。

| 维度（每项 1–5 分） | 评分问题 |
| --- | --- |
| 参考意图保留 | 是否保留参考的主要表达、冲突或笑点，而非只复述题目？ |
| 叙事连贯 | 角色关系、动作与前后因果能否从实际成片理解？ |
| 声画匹配 | 配音、对白、音效、音乐是否与当时画面一致？ |
| 剪辑节奏 | 镜头长度、衔接和声音节拍是否支持表达？ |
| 观看体验 | 画幅、清晰度、字幕可读性与视听舒适度是否正常？ |

统一锚点：1=目标基本未实现或严重不可用；2=多处明显问题；3=基本实现但存在可见缺陷；4=表达清楚且只有轻微缺陷；5=完整实现且没有观察到明显问题。评测必须附实际时间点证据、严重缺陷清单、评测者/模型版本与输入文件哈希；未能观看/听到某项时记为缺失，不能编造分数。

v1 自动合格标准预先固定为：系统按本方法的生产门槛已交付、通过技术门槛、五项均至少 3 分、均分至少 3.5、无严重缺陷、无研发介入，且未超过硬调用和请求截止限制。金额是否低于计划额度另报；费用未知时不能宣称金额预算已满足。严重缺陷包括异常嵌套黑边或画面畸变、重复/不可读字幕、意外片尾字幕或 END 卡、配音截断、核心内容明显错误。正常电影比例的对称黑边本身不算缺陷。协议阈值变更必须另报版本，不能根据当前结果临时放宽。

人工盲评至少抽取两组均衡的随机样本，并包含模型判定的合格与不合格结果；小规模首轮建议不少于每组 20%。报告各维度与人工的一致性、误放和误拒实例。LLM 得分是评测证据之一，不等于客观真值。

## 汇总指标与成本口径

按方法分别统计冻结 heldout 分母 **N=20**，开发案例另表。保留所有计划任务，不适配、失败和预算停止都进入 N。pending/unjudged 不从分母消失：同时报告终态覆盖率、外部评测覆盖率、已确认合格/N；未完成时该比值是已确认下界，不宣布为最终成功率，也不把全部 pending 伪装成确定失败。

| 指标 | 口径 |
| --- | --- |
| 技术完成率 | 通过技术门槛数 / N |
| 自动合格产出率（主指标） | 硬操作/时限内系统已交付、无研发介入且盲评达标数 / N |
| 人工干预率 | 发生研发/手工修改的任务数 / N |
| 严重缺陷率 | 严重缺陷数 / 已独立评测成片数，并另列该分母和评测覆盖率 |
| 质量 | 五个维度分别报告均值及分布，不能只给一个综合分；失败率同时展示 |
| 耗时与吞吐 | 每任务墙钟时间、整批开始至结束时间、自动合格条数/批次小时；写明实际并发与资源 |
| 成本 | 总运行费用 / 自动合格条数，失败和修订费用计入；无合格条数时不输出有限均摊成本 |

费用须区分**提供方已确认扣费**、估算、未知。没有金额收据不能当作 0 元；有不明费用时报告已知费用小计、成本覆盖率和“总成本未知”，不能用不完整小计宣称完整平均成本。素材建库、索引和首次观察的成本及耗时单列一次性投入；可另给摊销情景，不能隐藏到成功率之外或重复计为每次剪辑成本。

同一案例的两种方法形成配对比较，先报告差值与成功/失败数量。20 例属于首轮小样本，置信区间和失败分析比虚假的小数精度更有意义。后续消融只在明确需要验证“检索复用、声画规划、反馈修订”各自贡献时增加，并预先另定预算；本轮不无界增加实验。

## 给导师的交付

交付物应包括任务规格、架构与运行入口、冻结清单和版本、逐案例结果表、基线对照、成本/产出率、失败分析，以及代表成片和证据。当前阶段可陈述“已实现原型与评测机制，正在准备独立测试”，真实运行和独立评测完成后才填结果数字。成片是系统证据的一部分，不替代这些可复现的记录。

## 当前工具入口与实现边界

```bash
# 只读校验完整冻结集；准备态不足20例时显式增加 --preparation。
omni-eval check --manifest /absolute/path/manifest.json
# Linux后台批量；max_cost_cny=0拒绝启动。使用既有服务器凭证，不把Key放到命令行。
omni-eval --home /absolute/server/home start --manifest /absolute/path/manifest.json --output /absolute/server/home/shared/jobs/experiment_v1 --concurrency 5
# 批次结算后，按稳定run_id对实际参考+实际成片作独立声画评测。
omni-eval --home /absolute/server/home judge --manifest /absolute/path/manifest.json --output /absolute/server/home/shared/jobs/experiment_v1 --run-id heldout_v1/case_01/full
# 完整解码并核对实际成片，生成JSON、CSV、Markdown；不调用模型。
omni-eval collect --manifest /absolute/path/manifest.json --output /absolute/server/home/shared/jobs/experiment_v1
```

批量复用生产编辑器和服务器后台作业，最多配置5路；每路预留1GiB内存、768MiB磁盘，至少保留2GiB磁盘，FFmpeg单槽/2线程。运行身份写入共享registry；同一experiment不能换目录重新执行。未知调用或代码改变会停止新请求；已启动调用仍等待真实结果，截止时间不等于强制中断正在回传的请求。

共享预算在网络提交前通过阻塞文件锁占号，计入GLM视觉业务stage、TTS及Qwen服务，不退还失败/不确定请求的占号。为独立评测预留最多每计划任务1次调用额度（总额度不足时至少保留1次生成），生成阶段不能占用这部分；也不承诺每个任务都一定成功进入评测。每run上限同时包含生成和评测。本轮费用配置还在同一锁内预占保守费用，不能把操作次数或费用包络伪装成实付金额。

独立评测将参考与最终作品按顺序组合成同一声画包，保留两者完整时轴，参考等比补边，作品保留原画布，声音以AAC重编码；映射和文件哈希有收据。评审不接收方法标签、剧本或内部评分。当前实现逐条盲评；配对随机顺序比较、人工抽样和一致性分析仍需在有真实结果后执行，不能以工具存在声称已完成这些实验。

`max_model_calls` / `per_run_max_model_calls` 沿用业务调用字段名，精确定义为**台账操作数**：一次GLM视觉stage、一次TTS请求或一次Qwen声画评审各占1号。OpenCode为了调度MCP而进行的代理模型交互单独记录，不受这个操作数逐HTTP封顶；它不能被宣传为所有提供方HTTP请求数或账户级硬费用上限。失败/未知操作不退号。成本报告还需包括代理调用或订阅使用，不得漏项后报低成本。

每次运行复制同一个初始库的 observations、revisions 和 SQLite 索引。原始 media/provenance 保留在原处，按原绝对路径或兼容链接读取；新观察只追加到该次运行的副本。这样既能允许单次任务按需补看，也不会让先跑的参考改变后跑方法的起始条件。冻结库清单采用 `snapshot_version=1` 与 `files:[{path,sha256}]`，覆盖电影与素材库全部实际文件（排除锁及SQLite临时日志）；启动前验证实际字节，运行中核对文件集合和stat，源库改变则停止新工作。

当前“独立”仅指独立的新请求和方法盲评，不代表模型家族独立：生产声画审核与正式盲评目前均使用Qwen3.8-Omni-Flash，因此分数可能存在相关偏差。记录 reviewer_model、shares_model_with_internal 与 independence_scope；报告必须保留该局限。未完成独立人工抽样前，不能把这些LLM分数称为客观质量真值。

报告按run/method列出视觉stage、TTS、Qwen声画评审的实际台账操作数及预算占号数，包含失败和未知。占号发生在正式台账写入前，故可能大于实际操作数；两者分别报告，不拿占号当HTTP次数。OpenCode代理events是另一份使用证据，实际货币费用仍需计费收据，未知保持unknown。

正式产出率要求系统真正交付，不仅是退出码0和候选文件可播放。full须处于rough_to_skill_completed、生产联合门槛通过、实际声画内容可交付且技术确认通过；baseline_single_pass须处于rough_audio_ready、实际粗剪声画内容可交付（其精剪联合门槛按设计不适用）。两种方法均须最终画面审核pass，且该审核绑定本次最终视频SHA。若生产门槛拒绝但新请求盲评通过，计入candidate_external_quality_pass、保留分数与技术完成记录，不计automatic_qualified。这一口径在新的付费批次启动前固定。

## 本轮100元授权的费用控制

本轮用户授权累计新增费用100元。使用固定北京GLM-5.3-Flash、Qwen3.8-Omni-Flash和Qwen3-TTS-Flash及当前公开费率，单个业务操作先预占1元；按服务上下文上限和现有输出上限形成保守包络。共享锁内仅在累计保守费用加本次预占不超过90元时发起操作，另留10元余量。收到完整Token用量后按不含缓存优惠的刊例价回算；TTS按每字符最多2计费单位回算上界。failed/uncertain或用量缺失仍保留整笔预占，不退操作号、不重放请求。该数值是保守刊例价风险估计，不冒充已结算账单或提供方账户级扣费限额。

授权认领文件防止用新实验ID重新取得另一笔100元；原预算、失败和不确定记录必须保留。Coding Plan仍走固定套餐接口，不购买/升级、不切到其他付费代理；临时媒体上传使用官方免费的48小时存储：[官方说明](https://help.aliyun.com/zh/model-studio/get-temporary-file-url/)。不创建额外云资源。运行时遇到未知调用停新请求；业务进程失败时停止新案例接纳，让已在途的另一路结算，再由主agent诊断，避免把同一个系统错误重复扩散到全部40个计划行。

修复后可使用 `continue-pending --manifest … --output 原实验目录 --reason 具体诊断 --concurrency 5` 继续尚未启动的计划后缀。它要求原协调进程和既有子任务全部结算、没有未知调用，保留原授权、费用包络、请求占号与截止时间；已失败或完成的行都不会重跑。续批控制目录只保存进程与版本历史，不形成新预算。运行期间代码改变后，采集报告会单列版本偏差并保守排除自动合格，不能宣传为干净的冻结评测，也不能把版本偏差当作每条视频被人工编辑的证据。

评测入口要求服务器 `server.json` 配置可用的本地 `asr_model_dir`，并将同一路径传给两种方法，使用离线模式。`--asr` 关闭不代表创意配音不读参考语音；参考语音识别是该模式的既有前置步骤。部署时必须验证本地权重能加载，不能在每个子任务里临时联网下载。

吞吐报告区分worker时间区间与整批端到端区间。前者只覆盖编辑子进程，不能当成包含盲评的系统吞吐；后者从原实验开始计至最后一次已结算批次完成盲评与技术采集，包含等待与修复空档。未完成全部计划时仅给观察期吞吐与覆盖率；观察期吞吐随后可升可降，不是最终吞吐的下界，也不代表完整实验吞吐。固定计划分母下的已确认合格比例仍是最终产出率的下界。版本偏差与已确认人工干预分别统计，未知的逐案例人工介入不按零解释。

已结算子任务若只保留candidate_video/candidate_sha256，也可对该原样候选进行完整文件盲评，记录candidate_full_video，与最终成片的final_full_video区分。缺音轨候选的评测传输包仅补静音轨并明确标记output_has_audio_track=false，不补配乐、对白或字幕，不修改候选原件；原件技术检查仍保留音轨缺失失败，不能凭候选评分把它算成交付或自动合格。评测器源码SHA另存收据，量表与生产门槛不变。

模型计划及唯一修订均收到完整响应但未通过结构/证据校验时，仍记录该次失败。仅新版本明确的ModelProtocolRejected计划错误、两份完整回复与请求/响应哈希绑定均核验时，可继续接纳其他参考。回复若非合法JSON，还须核对保存的解析错误与原回复实际解析错误完全一致；这只分类失败，不修造模型输出或放宽素材证据校验。未决、传输错误、非计划协议错误及程序异常仍停止新工作。续批先独立评估既有已结算候选，再接纳新的生成任务，评测在同一调用/费用台账内计数。

用户明确要求延长时间时，可在同一预算锁内只修订有效截止时间，并保留原预算完整快照、原截止时间、用户授权和追加历史；调用计数、费用包络、实验/清单身份和既有停止/未知标记不能重置。报告注明时间授权变更及实际完整墙钟时长，不能把延期结果写成在原窗口内完成。

如果同一参考的已知失败原始 HTTP 收据明确给出 400/code1301，且 contentFilter 指明 user 输入拒绝，协调器核验参考、请求哈希与唯一已结算响应后，会让该参考尚未运行的另一方法记录真实预检失败，保留原始拒绝证据且不重新发送。该行仍在原计划分母中；报告须区分已接纳作业与实际发生模型操作的覆盖率，不能把零请求预检写成模型已运行。输入拒绝仅表示提供方对本次输入的决定，不证明视频实际不安全。未知/未决响应不适用此路径，仍停止新工作。

固定输出规格通过同一 worker 参数传给两种方法，并进入输入锁、计划提示与校验；不能只在报告阶段才检查。原模板默认竖屏导致的既有规格失败仍保留。评测传输包可对原作品整幅等比缩放和补边以完成拼接，并明确原画布尺寸；不裁掉原画布、不改原作品技术判定，传输补边与原作自身黑边分开说明。没有收据的失败打包中间件归档后重建；存在收据但缺少绑定时拒绝重建。

`final_video` 字段名本身不证明生产交付。报告按该方法实际生产门槛区分 `final_full_video` 与 `candidate_full_video`，未交付预览即使沿用该字段也计为候选；旧评分与调用收据不改写、不重新请求。技术检查每次从原文件probe并完整解码，缓存结果须与实测相同；传输包的音轨存在、时长及原画布同样从原文件核验。明确为assistant输出拒绝的1301仅结算原失败行并允许其他计划任务继续，不当成user输入拒绝，也不会由此重发原调用。
