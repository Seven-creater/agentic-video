# INC-20261029-04 宫格外层 JSON 多一个右括号,回退解析取到内层格子,整任务崩溃

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-10-29 |
| 影响范围 | question_first 生产运行的 skim 回复解析;致命停机——一次坏 JSON 让整个任务崩掉 |
| 状态 | 已修复(c3beebb) |
| 相关提交 | c3beebb |
| 相关任务 | 真实回复:第 65 页(`question_first.py` 当时 313 行 KeyError 'tiles');用真实回复做测试 |

## 1. 问题长什么样
第 65 页 skim 回复的 JSON 末尾多了一个 `]`,整体解析失败;回退解析(从文本里找第一个 `{` 开始 raw_decode)取到了**第一个内层 tile 对象**并把它当作整份回复;下游 `KeyError: 'tiles'` 在 question_first.py:313(当时行号)炸掉整个任务。

## 2. 怎么查出来的
真实运行崩溃栈定位到 `KeyError 'tiles'`;检查回退解析逻辑确认其不校验取到的对象是不是最外层结构。

## 3. 根因
代码问题(校验漏洞,两层):①回退解析接受"任意第一个可解析对象"冒充整份回复;②单页解析失败没有被隔离成"丢一页",而是让任务崩溃。

## 4. 解决方案(c3beebb)
- `parse_json_object` 只接受最外层对象:先剥代码围栏(````json`),再从首个 `{` 尝试整体 raw_decode;外层坏了就明确报"没有完整JSON对象",不再退而取内层对象。类型检查:非文本/非 dict 均明确报错。
- 新增 `salvage_tiles`:外层 JSON 损坏时逐格抢救——扫描文本中每个可解析对象,只收带整数 `n` 的扁平格子对象,其余交给 validate_skim 逐格过滤;skim 回复缺 `tiles` 列表时进入抢救,抢救结果标 `salvaged_from_invalid_json=True`。
- 单页、单段不可用只丢它:skim 的坏回复抢救不出任何格才失败,损失限于那一页/那一格,任务继续;非 skim 阶段不抢救(结构不同)。
- 收到的原始字节先落账再解析的重放安全保持不变(重跑复检同一字节,不补发)。
通用性:纯解析层规则,任何页、任何影片同样成立。

## 5. 为什么不用其他方案
- 维持"取第一个对象"的回退:正是本崩溃的直接原因。
- 坏 JSON 即整页丢弃:第 65 页 36 格里可能仍有大量合法格(v2 监控里整表零产出只占 6/136),抢救的单调下界更优。
- 对失败页重发:违反不重发规则。
- 其余备选:未讨论。

## 6. 怎么验收
新增测试用真实回复做用例(单页坏 JSON 抢救、无 JSON 即失败、单格丢失只影响该页),`tests/test_question_first.py` +29 行;专项验收输出未单独归档,行为由后续全量回归(f1/c1/w1/e2e 各轮)持续覆盖。

## 7. 量化数据
v1 实验中 JSONDecodeError 整页损失 2/136 页;c3beebb 后同类回复以格级抢救保底(该页抢救格数未记录)。修复后因 skim 坏 JSON 导致的任务崩溃:0。

## 8. 经验与后续
- "回退解析"必须保证取到的是预期层级,否则宁可用文本扫描做结构化抢救。
- 失败隔离的最小单位是"页/格",不是"任务"。
