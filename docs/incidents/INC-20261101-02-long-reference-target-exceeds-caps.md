# INC-20261101-02 长参考的分镜目标时长超过渲染上限，提示词与校验互相矛盾

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-11-01 |
| 影响范围 | 分镜路径规划（参考 >150 s 时）；潜在必然失败的规划 |
| 状态 | 已修复（4b3d28f） |
| 相关提交 | 4b3d28f |
| 相关任务 | sb_02_雪山救狐狸_11010232（误用 161.9 s 参考，已停止，见 INC-20261101-04） |

## 1. 问题长什么样
161.9 s 参考产生 32 格分镜（14 个核心格）、39 道题。`storyboard_targets` 给出目标时长 [129.5, 194.3] s，而同一次规划校验仍执行创作路线上限 `max_duration_s=180`、`max_segments=32`。

## 2. 怎么查出来的
误用长参考后检查分镜和出题规模，对照 contracts.validate_plan 默认参数（180 s / 32 段）与 storyboard.py 的目标计算，发现上界 194.3 s > 180 s。

## 3. 根因
deb8043 的目标区间只按参考时长 ×[0.8, 1.2] 计算，没有读取实际执行的渲染上限；提示词和校验各自使用不同的数。属于提示词与校验不一致（代码问题）。

## 4. 解决方案
`storyboard_targets(..., max_duration_s, max_segments)`：上界 = min(1.2×d, 上限)，下界 = min(0.8×d, 上界)，记录 `caps_applied`；提示词、校验、`storyboard_plan_policy` 共用同一函数并由 pipeline 传入本路线实际上限（progress_driven 为 None）。核心格多于段数上限时，提示词说明一个 slot 可承载多个核心格。对任何长度的参考成立。

## 5. 为什么不用其他方案
- 截短分镜：丢故事内容。
- 放宽 180 s 上限：渲染与预算上限另有依据，不在本问题范围。

## 6. 怎么验收
新增测试：161.9 s → [129.5, 180]；30 s → [24, 36]；progress_driven 不截；14 个核心格 5 个 slot 通过。全量测试失败集合等于基线，回放 0 退化，fault_check 关键项为 0。

## 7. 量化数据
目标上界 194.3 s → 180 s。服务器未实际跑长参考规划（任务已停）。

## 8. 经验与后续
程序给模型的任何数值目标都必须与校验同源。正常模板筛选限制在 8–45 s（e2e_night.sh），长参考仍属边界情况。
