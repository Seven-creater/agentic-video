## 1. 问题长什么样
- 薛甄珠 A 线连续两次停在写剧本：`model_protocol_repair_exhausted:material_scene_script_1_1`。每次尝试的 `finish_reason` 都是 `length`，推理用了 65027～65535 token，正文 0 字。
  - release 82d75c818816 上 3 次；
  - release 8ed3796a09e6（按需要分配预算之后）上又 2 次。
- 用户追问："选中餐厅的 28 秒是整个餐厅场面只有 28 秒吗？"

## 2. 怎么查出来的
1. **画面少用**：读选中的 3 个窗口的看片记录和保留的镜头：
   - 第 1 窗：13 秒剧情，保留 12.5 秒；
   - 第 2 窗：约 10 秒剧情，**只保留 1.6 秒**；
   - 第 3 窗：保留约 14 秒。

   查目录：这场居酒屋戏在原片里从"到达餐馆"（15446 秒）到"离开"（约 15540 秒）约 80 秒；程序自动往前、往后补看的两个窗口，都被连续性复核判成了"另一个场景"（店外 / 店内 / 店门外），没有并进来。
2. **是不是系统性的**：扫描服务器上全部历史任务：
   - 92 次逐窗看片里，剧情画面最终只保留了 60%；最近几个模板只有 32%～53%（02 35%、17 32%、03 44%、18 47%、21 53%）；20 次保留不到 25%。
   - 拆开环节看：54 个有核对记录的窗口，剧情 849 秒，原声核对后剩 511 秒（**丢 40%**），再经场景范围和冲突剔除剩 422 秒。Qwen 平均覆盖窗口 95% 的时间，其中"不确定"143 秒，被整段丢掉。
   - 相邻窗口补看 124 次，有 50 次（40%）没有并入原场景。
3. **剧本死循环**：在服务器上把同一份剧本提示词直接发给 GLM（不进账本，并行 3 组）：

   | 组别 | 结束原因 | 正文 | 推理 token |
   |---|---|---|---|
   | 原样（带字数上限） | length | 0 字 | 65086 |
   | 字数上限翻倍 | length | 0 字 | 65216 |
   | 去掉字数上限 | stop | 9917 字 | 56554 |

   结论：只要带着字数上限写剧本，GLM 就会在推理里反复数字数、改写，直到用光额度；上限放宽一倍也一样。去掉上限就能写出来。

## 3. 根因
- **原声核对**：Qwen 判为"不确定谁在说话"的片段被整段丢弃（`if part['uncertain']:continue`），即使画面本身完全能用。
- **连续性分组**：v3 定义按"地点"分组，人物从店外走进店内被当作换场，同一场戏被拆成几组，补看的相邻窗口接不上。
- **剧本长度**：画面预算（INC-17-05）要求在剧本阶段按精确字数写，模型陷入"数字数—删改—再数"的循环；修复反馈只报 `Expecting value`，于是同样的循环重来三次。
- 三者叠加：画面被低估 → 预算很紧 → 剧本要压缩得很狠，又要逐字计数 → 死循环。

## 4. 解决方案（用户 11-17："大胆让 GLM 发挥，系统要做的是巩固好"）
- `scene_casting.verify_source_speakers`：不确定的片段**保留**，标注 `speech_uncertain`，不认任何人为说话人（`speaking=[]`、`dub_speaker_ids=[]`）。可以作为别人说话时的反应、听者镜头，由看得到画面的 GLM（剧本、排片审核）决定怎么用；永远不能当作说话镜头，也就不能当角色首次开口的锚点。
- `material_browser.continuity_prompt`（策略升级到 v4）：同一批人物、时间连续、同一件事算一场戏，人物沿连续行动换位置（店外走进店内、门口走到桌边）不换组；回忆、想象、梦境、换日、与前后不相连的场所仍要换组。
- `joint_dialogue`：
  - 改编模式下，剧本只给建议长度（`suggested_chars`），提示词写明"不必逐字计数"，校验不再因为字数打回；
  - 长度改由改编计划控制：每个角色所需空间 = max(原句 × `PLAN_KEEP`(0.8)，轮次 × 6 字)，按所需分配预算。删句子是选择题，GLM 已经两次一次通过；
  - 严格复刻模式保持原来的硬上限。
- `pipeline`：识别"推理用尽、正文为空"，修复反馈改为"直接写出 JSON，不要逐字计数、不要反复自检"，并且不再附加误导性的"JSON 出错位置"提示。

## 5. 为什么不用其他方案
- 剧本上限放宽：对照实验证明，放宽一倍照样死循环。
- 原声不确定的片段先多看一次嘴型再决定：多一层判断，而且用户认为看画面、对嘴型本来就是 GLM 的工作，交给后面看画面的审核即可。
- 只调连续性分组的提示词措辞、不改定义：v3 的问题出在"按地点"这个定义本身。

## 8. 经验与后续
- 给模型的约束，要先确认它能不能完成；做不到的约束会让模型陷入推理循环，而不是报错。
- "素材不足"在很多情况下是我们自己丢掉了素材：看片后的每一道过滤，都要统计它丢了多少画面。
- 遗留：
  - 场景范围裁剪和重叠冲突剔除还丢了约 89 秒，原因未查；
  - 粗看阶段每个片段最多 3 个窗口的上限还没改；
  - B 线没有同步。
