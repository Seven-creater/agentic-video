| 影响范围 | 创作路线重跑(`--reuse-plan`)与配音;浪费调用(重复付费 TTS、重新规划) |
| 状态 | 已修复(42516dc、5933088、9aac311、a757c81) |
| 相关提交 | 42516dc、5933088、9aac311、a757c81 |
| 相关任务 | 重放归档任务链(kuangbiao 多层 evaluations 嵌套) |

## 1. 问题长什么样
对同一创意任务的评测性重跑(在上一轮输出目录下开子任务)时,上级任务已收到并付费的规划与 TTS 无法复用:规划只看直接父级,多层嵌套链上找不到最初规划;完全相同绑定(同文本、同音色)的 TTS 被再次合成、再次计费。

## 2. 怎么查出来的
从重放归档的任务链(最多 11 层 evaluations 嵌套)核对调用账本,同一 text/voice 组合在链上多次出现;代码走查确认复用查找不沿链追溯(`--reuse-plan` 只查一层)。

## 3. 根因
代码问题(流程分支):复用查找的 lineage 范围不足;TTS 请求没有跨任务的去重键。

## 4. 解决方案
按 `docs/CREATIVE_ROUTE_CHANGES_20261027.md`"重跑与复用(10-27)":
- `--reuse-plan` 沿任务链一路追溯到最初收到的规划,每一层校验文件是否被改动(sha)。
- 配音复用:在上级任务链中找到完全相同绑定、且已收到的 TTS 直接复用,不再付费;复用配音单独计为 `reused`,不算本任务付费请求;上级任务中结果未知的配音仍被拦截(不重发规则)。

通用性:按"文件哈希 + 绑定键"匹配,与模板无关。

## 5. 为什么不用其他方案
- 重新规划/重新合成:多花一次模型与 TTS 费用,且结果可能漂移;能确定复用就复用。
- 对上级结果未知的配音也强行复用/重发:违反"未知不重发"规则;保持拦截。
- 其他备选:未讨论。

## 6. 怎么验收
本批自身验收输出未记录;行为由后续批次全量回归与重放(191→203 行基线)持续覆盖。已知局限照抄文档:复用依赖上级任务文件可读且未被改动。

## 7. 量化数据
节省的调用/费用次数未记录(重放归档可按 `reused` 计数字段统计,后续可测)。

## 8. 经验与后续
- 评测式开发的目录结构(层层嵌套 evaluations)必须与复用机制配套,否则每一次迭代都全额付费。
- 遗留风险:上级文件被移动/删除时复用失效,回退为正常付费路径。
