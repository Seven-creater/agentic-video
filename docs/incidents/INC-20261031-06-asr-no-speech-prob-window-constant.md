# INC-20261031-06 按 no_speech_prob≥0.6 判台词可忽略，整条参考台词归属校验失效

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-10-31 |
| 影响范围 | 分镜步骤 ASR 归属校验；漏检（薛甄珠、黑虎全部台词可不归属） |
| 状态 | 已修复（6c940af） |
| 相关提交 | 6c940af |
| 相关任务 | e2e_21_薛甄珠吵架_10312028、qfs_full_heihu_20261029_b 的 reference_asr.json |

## 1. 问题长什么样
薛甄珠 11 句 ASR 的 no_speech_prob 全为 0.62（avg_logprob 都是 -0.6），其中 10 句是真台词；黑虎 14 句全为 0.73，全是真台词。规则"no_speech_prob ≥0.6 可忽略"使这两条参考的全部台词不需要归到分镜格。

## 2. 怎么查出来的
统计 7 个模板 reference_asr.json 每句的 no_speech_prob：薛甄珠、黑虎每句完全相同，其余 5 个模板全部 <0.6。确认该值是按整段音频窗口给出的常数，不是逐句概率。

## 3. 根因
规格（S1_storyboard.prompt.md 校验 e）假设 no_speech_prob 是逐句置信度；实际 faster-whisper 的这个值按解码窗口给出，短参考常常整条只有一个窗口。属于对数据语义的错误假设（代码问题）。

## 4. 解决方案
程序只把空文本判为可忽略；no_speech_prob 只作为信息传给模型。新增模型输出 `asr_rejected: [{id, reason}]` 显式剔除噪声或误识别，id 必须存在且不能同时出现在 lines 中，剔除数 ≤ 非空句数 25%（向上取整，至少 1 句），超出报违规并列出被剔除的句子；结果写入 storyboard.md。

## 5. 为什么不用其他方案
- 提高阈值到 0.8：黑虎 0.73 恰好过关只是巧合，窗口常数的本质不变。
- 用 avg_logprob 判：同样按窗口给出（薛甄珠全为 -0.6）。
- 完全不允许剔除：参考开头的误识别（薛甄珠第 0 秒"Base"）会迫使模型硬塞进某格。

## 6. 怎么验收
新增测试：薛甄珠真实形态（11 句、全 0.62）剔除"Base"通过、剔除 4 句（>25%）违规；高 no_speech_prob 句子不剔除也不归属必须报 unassigned。第二次试跑 7 模板全部成功，`asr_rejected` 均为空，所有台词有归属。

## 7. 量化数据
修复前薛甄珠 11/11、黑虎 14/14 句可忽略；修复后 0 句可忽略，0 句被剔除。

## 8. 经验与后续
使用识别器的置信字段前先看它在真实数据上的分布是否逐句变化。
