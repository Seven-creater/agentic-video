## 1. 问题长什么样
`AssertionError:preview_failed:{CoverageError:joint_coverage_insufficient:['scene_1']:no unambiguous first appearance for 妃子}`。停机前共 69 次调用，剧本、剧情复核、TTS 音色都已经做完。

## 2. 怎么查出来的
GLM 诊断见 `night_diag/18__1116_0910_glm.md`。它分不清是"锁定的镜头组里没有锚点镜头"，还是"有但没被选上"。Claude 到服务器只读核实，结果如下：
- `material_lock.json` 里 scene_1 共 19 个镜头。16 个是两人同框，两人都登记为配音角色。妃子单独出镜的只有 3 个：`shot_6d7e3238c80b`、`shot_202b04839182`、`shot_76873b16e03b`，看片记录都是"小兽近景，眼睛含泪，抬手擦拭鼻嘴"。
- 排片审核（`glm_002_material_scene_schedule_1_1*`）的 eligible_shots 里包含这 3 个镜头。审核只把它们列进 l5、l6、l7 的选项，issues 原文：`小兽含泪擦拭三镜与l1–l4阶段微笑状态不符，仅列入l5/l6与静默`。
- 妃子的首句 l2"骑士大人，我记得的。"是微笑应答。按锚点规则 `anchor_view`，配音角色首次开口必须用画面里只有本人的镜头，而符合条件的镜头全都是哭。

## 3. 根因
- 直接原因：素材里妃子能单独辨认的镜头只有结尾哭的那一段，情绪和她首句不相容。审核正确拒绝，锚点规则也正确拒绝。
- 结构原因：和 INC-20261116-04 一样。选角时的锚点检查（INC-20261115-04）只看窗口里"有没有单独出镜的镜头"，不看情绪能不能配上首句。剧情复核不知道首次露脸规则，所以放行了。等到配音完、排片时才发现，这时已经没有退回去改的环节。

## 4. 解决方案
本次不修。
- GLM 修复 4 建议：锚点不够时，由程序自动补一个单独出镜的镜头当 0.8 秒开场。这样做等于用含泪特写去配微笑的台词，违反"画面先行"，所以不采纳。
- GLM 修复 1、3、5（组选择考虑锚点、写稿时必须包含 anchor_shots、预检与排片用同一标准）：本例中锁定的组里有锚点镜头，只是情绪不符，所以这几条都救不了本例。
- 待用户决定的方向：
  - 方向一：选角时的锚点检查改为同时核对参考首句的情绪和动作，参考台词在选角时已经知道；不满足就扩窗补看，或判为素材缺口。这在花钱做 TTS 之前就能停下。
  - 方向二：排片失败后回到剧本按画面改写。本例中首句的情绪是参考规定的，改写救不了，所以方向二不适用。

## 5. 为什么不用其他方案
- 放宽锚点规则：会回到 INC-20261115-04 之前的问题，两个配音角色同框时，观众分不清是谁在说。
- 直接归为 material_gap 跳过：结论虽然接近"素材不足"，但发现得太晚，已经浪费了 69 次调用和 TTS。应该在上游提前拦下，而不是把这类错误一律改名。

## 6. 怎么验收
未修复，无验收。修复后，同类情况应在选角阶段就停下或扩窗，不再进入写稿和 TTS。
