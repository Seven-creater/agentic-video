# INC-20261029-15 自动流水线清理脚本 sed 误删 SSH 那一行,服务器步骤全部没执行

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-10-29 |
| 影响范围 | 服务器自动流水线(运维脚本);运维阻塞——服务器侧步骤整体跳过,下游对着空数据产出错误小结 |
| 状态 | 已处理(手动补跑;无代码修复,教训固化为检查规范) |
| 相关提交 | 无 |
| 相关任务 | 未记录(涉事脚本与运行目录未归档) |

## 1. 问题长什么样
自动流水线的清理脚本用 sed 编辑脚本内容时把 SSH 那一行误删;后续服务器步骤全部没执行,报 `no such file or directory: cat > ...`;GLM 步骤对着空数据照常写了小结——错误结论被包装成正常产出。

## 2. 怎么查出来的
服务器侧文件缺失的报错回溯;检查清理脚本的 sed 表达式确认匹配范围过宽,把含 SSH 的行一并删掉。

## 3. 根因
操作问题(脚本缺陷):sed 匹配过宽误删关键行;且流水线缺少"关键变量非空"的前置检查,空数据没有阻断后续步骤。

## 4. 解决方案
手动补跑被跳过的服务器步骤。无代码修复(一次性脚本)。

## 5. 为什么不用其他方案
- 未讨论(一次性运维脚本,重写价值低;教训以规范形式沉淀)。

## 6. 怎么验收
补跑后服务器产物齐全、结论恢复正常。无自动化验收。

## 7. 量化数据
未记录(受影响步骤数、补跑耗时未归档)。

## 8. 经验与后续
- 改完脚本必须先语法检查再运行;流水线关键步骤前检查关键变量/文件非空,空数据要硬失败而不是让下游"正常"消化。
- 与 INC-20261027-08 同类:一次性脚本也要有失败即停与产物自检。
