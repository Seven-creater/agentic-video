# INC-20261116-02 看片阶段报错不可操作，三次修复撞三道校验后停机（黑虎阿福）

## 1. 问题长什么样
`AssertionError:creative_stopped_before_usable_draft:model_protocol_repair_exhausted:material_scene_discovery_observe_1`，停在第一次看片，抛出位置 `pipeline.py:1898`。窗口长 17.0 秒，程序检测出 37 个镜头切点（最短 0.067 秒）。同一阶段三次回复依次撞了三道不同的校验：
1. glm_065：`finish_reason=length`，生成 32768 token 中推理占 32733，正文 0 字符，报 `Expecting value`；
2. glm_066（第一次修复）：把多个镜头合并成 `"cut_id":"c1-c6"`，报 `unknown cut or invalid times`；
3. glm_067（第二次修复）：37 个镜头逐个写全了，但 `visible` 里填了自造标签 `"蓝帽白色圆生物(未确认ID)"`，报 `segment contains unconfirmed actor: visible`。修复次数用完，停机。

## 2. 怎么查出来的
值守脚本先用 `night_diag_case.py` 取证（`night_diag/15__1116_0321.txt`），再由 GLM-5.3（max）写只读诊断（`night_diag/15__1116_0321_glm.md`）。Claude 对照源码核实了以下几点：
- `autonomous_material.py:178-195`：看片提示词只写了"逐一观察，不能跨cut"和"只列实际核实的actor_id，不创造ID"。它没有说明 cut_id 不能写成区间，也没有说明看得见但没登记的人物该写在哪里。
- `autonomous_material.py` 里 validate 给出的两条报错不指出是哪个值错了，也不说明正确写法；`pipeline.py:1973 repair_hint()` 对这两种报错也都没有对应的修复提示。
- 上游登记阶段（glm_064）没登记上第二主角 P2：裁图切掉了头部，返回 unresolved。所以 observe 阶段只能引用 2 个 actor_id，模型只好自造标签来如实描述在场人物。

## 3. 根因
- 直接原因：校验规则和提示词不一致，报错又不可操作。提示词没把"单个 cut_id"和"只能填 confirmed_actors"这两条硬规则讲清楚，也没给未登记人物留出合法的写法。修复轮看到的报错只是一个泛泛的错误码，模型每次只能换一种猜法，结果撞上下一道校验。这和 INC-20261115-05、INC-20261115-08 属于同一类代码问题（报错不可操作）。
- 根本原因（推断，未单独修）：第一次回复的推理耗尽了生成上限。镜头切点越多，输出越长，推理余量越小。登记阶段每个角色只取一张裁图，裁坏了就没有第二次机会，这是另一个独立缺口。

## 4. 解决方案
只改了 `autonomous_material.py` 的 `inspect()` 一个函数，规则对所有窗口、所有模板一样：
- 提示词补了三条：cut_id 必须恰好是输入里的一个 id，不能写区间；多个 cut 各写一个 segment，重复论述可以省略，但不能合并；visible 等数组只能取自 confirmed_actors，看得清却没法核实的人物写进 action 和 uncertainties，不要自造标签。
- 报错改成可操作的写法：
  - 未知 cut_id 时，报出错误的值和合法范围（`c1..cN`），并要求每个 cut 写一个 segment；
  - 时间不合法时，报出该 cut 的边界；
  - 出现未确认人物时，报出这些值和允许的 ID 列表，并说明应该改写到 action 和 uncertainties 里。
- 校验强度没有变化：区间写法和自由文本依然会被拒绝，下游把 actor_id 当键用的绑定不受影响。
- 续跑：observe 提示词变了，会走 `pipeline.py` 的 `revised_scene` 分支重新请求 observe。已付费的 portraits 和 entities 回复照原样复用。

## 5. 为什么不用其他方案
- GLM 建议的方案 A：把短于 1 秒的镜头合并成"最小观察单元"。没有采用。合并后，一个单元可能跨过真实切点，visible 会变成两个镜头里人物的并集，排片时就可能把"人物可见"标到实际上没有这个人的帧上，违反画面先行原则。而且 glm_067 已经证明 37 个 cut 逐个写完能放进生成上限，体积并不是必然超限。
- 校验器把 `c1-c6` 区间或自由文本当成合法写法：等于把违规写法合法化，还会污染 actor_id 绑定。
- 允许 observe 阶段自己新建 actor_id：会破坏跨窗口的身份登记规则。
- GLM 建议的方案 C（裁图坏了就换个时刻重裁、再登记一轮）：方向合理，但它要改登记链路，而且"裁图有缺陷"这一判断要靠自由文本，容易误判。本次先不做，记为后续项。
- 当作素材不足跳过：与证据不符，这个窗口里 4 个角色都清楚可见。
- 调高修复次数上限：治标不治本。报错不可操作的话，多给几次也是乱猜。

## 6. 怎么验收

  - 提示词里写有两条硬规则；
  - 区间写法的报错包含错误值和 `c1..c3`；
  - 自造标签的报错包含该标签、`['A1']` 和 uncertainties；

## 8. 经验与后续
- 新增或收紧任何校验时，提示词里必须写清同一条规则，报错要报出错误值和正确写法（与 INC-05、INC-08 是同一条经验）。
- 遗留问题 1：登记阶段每个角色只有一张裁图，裁坏了就登记不上（GLM 方案 C），需要设计一个基于结构信号的重裁判据。
- 遗留问题 2：镜头切点很多时，推理可能把生成上限耗尽。如果补跑时第一次回复还是正文为空，再评估怎么改。
