# INC-20261028-05 GLM 官方 MCP 把深度思考写死开启:看片调用极慢甚至无输出

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-10-28(宫格粗看实测) |
| 影响范围 | GLM 视觉调用(看片/宫格粗看);浪费调用(思考耗尽 token 无输出)与严重耗时(历史看视频类中位 171 秒) |
| 状态 | 已修复(绕过:所有 qfs 调用显式 `thinking.type=disabled`;宫格粗看一页 12–49 秒) |
| 相关提交 | 无独立提交(调用参数;随 Q1 实验脚本与 cf9a1aa 生产接入固化,请求体断言 `thinking.type=="disabled"`) |
| 相关任务 | 方案文档实测节(2026-10-28,KFP1 1800–2700 秒、156 镜头、5 页 6×6、15 次 GLM 调用) |

## 1. 问题长什么样
官方 MCP 默认把深度思考写死开启:一页宫格 492 秒、思考用光 16384 个 max_tokens 仍无结果;另一页 372 秒才出结果。这解释了历史"看视频"类调用中位 171 秒、p90 328 秒的耗时。

## 2. 怎么查出来的
宫格粗看对照实验(同 5 页素材):思考开(官方默认)492 秒/无输出、372 秒;思考关 12–32 秒、36 格全部按格式返回。再压并发:4 路 13–32 秒、8 路 13–49 秒,均无限流。

## 3. 根因
外部服务问题(官方 MCP 参数写死);代码侧的对应动作是调用方必须显式关闭并断言该参数,防止回归。

## 4. 解决方案
- 所有 GLM qfs 调用请求体显式 `"thinking":{"type":"disabled"}`(Q1 起固定,测试断言请求携带该字段)。
- 粗看定位为"只圈位置":认人交给精看大图+样图比对;角色表带"其他"并补配角,不强行套固定名单。
- 由此得到的新速度模型:一部片约 1300 镜头 ≈ 37 页宫格,8 路并发粗看一遍约 3 分钟,三部约 10 分钟。
通用性:与影片、题目无关,是调用层参数。

## 5. 为什么不用其他方案
- 保持思考开启换更细判断:实测慢 10 倍以上且有无输出风险;粗看不需要细判断("摔倒、狼狈"题漏判少,开思考只是更细但代价不成比例)。
- 用其他视觉接口/本地模型:不在本问题范围(本地无 GPU,见 INC-20261028-04 第 5 节 FlashVID 结论)。
- 其他备选:未讨论。

## 6. 怎么验收
实测对照见第 2 节;Q1 测试断言请求携带 `thinking.type=="disabled"` 与 `X-Title` 计费头;v1/v2 实验(161/155 次调用)与生产 cf9a1aa 运行均按此参数。

## 7. 量化数据
思考开:一页 492 秒、16384 token 无输出;另一页 372 秒。思考关:一页 12–32 秒;8 路并发 13–49 秒、无限流;一页输入约 2311 token(方案文档另记约 2300)。速度提升一个数量级以上。

## 8. 经验与后续
- 外部服务的默认参数要当配置缺陷对待:显式设置+测试断言,防止上游变化悄悄拖慢全链。
- 宫格页输入仅约 2300 token,整图被压缩得很小,每格细节有限——这是认人失误的结构原因,精看必须放大比对。
