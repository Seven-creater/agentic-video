# INC-20261115-04 说话角色缺少可单独辨认的镜头，直到配音后的排片才发现

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-11-15 |
| 影响范围 | 选角校验 `story_dialogue.validate_selection` 与排片 `joint_dialogue._allocate` 标准不一致；浪费一轮配音（31 句） |
| 状态 | 已修复，发布 `scene_v1_schedule_8d1532f48638` |
| 相关提交 | 无 git |
| 相关任务 | `fast_resume_20261115_015322` |

## 1. 问题长什么样
31 句配音已全部合成，排片阶段报错：`no unambiguous first appearance for 摊主`。选角阶段的校验却放行了这组演员。

## 2. 怎么查出来的
- 选角校验只要求角色有 `speaker_view` 镜头。骑士和白熊同框、两人都在 `dub_speaker_ids` 中的镜头，在选角阶段被算作骑士可以配音的画面。
- 排片对“角色第一次开口”额外要求：要么是原片中本人说话的镜头，要么画面里没有其他有台词的角色。见 `joint_dialogue.py` 的 `_allocate`。
- 两处标准不一致，缺口只能在最后才暴露。

## 3. 根因
同一条规则在流程上下游被实现成两个不同版本，上游的版本更宽松。这是一个流程分支问题。

## 4. 解决方案
- `joint_dialogue.anchor_view(shot, actor, bound)`：把排片的首次亮相条件抽成一个函数，`_allocate` 改为调用它，行为不变。
- `story_dialogue.validate_selection`：对每个有画内台词的角色，在所选窗口中检查是否存在 `anchor_view` 镜头。没有就报错，并提示返回 expand 补看同场画面或改选候选；该报错走选角的协议修复，模型可以在修复中改为 expand。
- 素材时长不做硬拒绝：下游允许复用静态镜头补足时长，原有的容量检查保持不变。

## 5. 为什么不用其他方案
- 放宽排片的首次亮相规则：观众分不清新声音属于谁，用户认可的线路保留了这条规则。
- 在排片时自动换场景：配音已经合成，换场景要重写剧本、重新配音，代价更高。

## 6. 怎么验收
- 测试 `AnchorTests`：同框且都可配音的镜头不能作为锚点；有静默同伴的单人可配音镜头可以；原片本人说话的镜头可以；缺摊主锚点的选角被退回并提示 expand；每个说话角色都有锚点时通过。
- 全量 134 passed。真实续跑验证待选角阶段结束后补充。

## 7. 量化数据
- 修复前：问题在第 31 句配音合成之后才暴露。
- 修复后：在选角时暴露，配音合成次数为 0。真实数据待补。

## 8. 经验与后续
- 下游的硬性条件应在流程中尽早用同一个函数检查，不要在上下游各写一遍。
