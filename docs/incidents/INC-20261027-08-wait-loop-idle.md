# INC-20261027-08 后台等待脚本空转 6 小时:until 循环条件永不成立

| 项 | 内容 |
|---|---|
| 发现日期 | 2026-10-27 |
| 影响范围 | 服务器运维(等待 GLM 审核完成的后台脚本);运维阻塞——占用会话与注意力,不产生花费 |
| 状态 | 未修复(一次性事件,手动停止;教训已沉淀为操作规范) |
| 相关提交 | 无 |
| 相关任务 | 未记录(具体脚本与所属运行目录未归档) |

## 1. 问题长什么样
一个"等待 GLM 审核完成"的 until 循环持续空转约 6 小时:判断条件始终不成立,而 GLM 审核实际早已完成;脚本只在 sleep,不发起任何调用、不花钱,也没有人注意到它没退出。

## 2. 怎么查出来的
人工发现审核结果早已产出,回看后台会话发现循环仍在跑;核对条件表达式确认其判断的状态永远不会满足。

## 3. 根因
操作问题(脚本缺陷):等待条件写错(或判据指向不会更新的字段),且循环没有超时上限、没有完成后的自检退出。

## 4. 解决方案
手动停止该脚本。无代码修复(一次性运维脚本)。

## 5. 为什么不用其他方案
- 给该脚本补条件/超时:脚本为一次性产物,重写价值低;教训固化为规范更通用。其余备选未讨论。

## 6. 怎么验收
无(未做代码修复)。事后检查确认 GLM 侧已完成、无重复调用。

## 7. 量化数据
空转时长约 6 小时;花费 0 元(只在 sleep)。

## 8. 经验与后续
- 所有等待脚本必须设超时上限,并在目标完成后核实脚本确实退出;后台任务结束时要有显式的完成信号,不能靠"没消息就是完成了"。
