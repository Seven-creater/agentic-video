# INC-20261117-01 压字幕后的校验把 1 个时间刻度的拼接误差当成"画面时间轴变了"，成片交付成无字幕版

| 项 | 内容 |

| 发现日期 | 2026-11-17 |
| 影响范围 | 预览出片的字幕烧录步骤（A、B 两条线共用的 `audio_render.py`）；错误成片（缺字幕），不停机 |
| 状态 | 已修复：A 线 22b092d（release 11093337e5ad），B 线 de6b775（release 09dccf2d443d） |

## 1. 问题长什么样
B 线薛甄珠出片后，`检查记录.json` 里写着 `subtitle_mode: srt_only`、`subtitle_error: ValueError:audio_render_video_geometry_or_fps_changed`，交付的是 `final_mixed.mp4`（没有字幕）。逐句检查图上看不到中文字幕。服务器上其实已经生成了 `final_subtitled.mp4`（24.3 MB）。

## 2. 怎么查出来的
- 报错来自 `src/omni_story/library/audio_render.py:262/271` 的 `_verify_video`。
- 用 ffprobe 对比两个文件：
  - 两边都是 1280×720，都是 3637 帧；
  - avg_frame_rate 不同：无字幕版是 55864320/1862143，字幕版是 30/1；
  - 时长相差 0.000065 秒。
- 逐帧读取 `best_effort_timestamp`（时间基 1/15360）：前 3338 帧完全一致；从第 3338 帧起，无字幕版的每一帧都比字幕版早 1 个刻度，共 299 帧，差值全是 −1。
- 排除的假设：分辨率变化（没有变）、丢帧或加帧（帧数相同）、帧顺序变化（其余帧完全一致）。

## 3. 根因
- 直接原因：`_verify_video` 在帧率字段不同时，改为逐帧比较显示时间，但要求每一帧都**完全相等**。
- 根本原因：拼接无字幕版时，后面某段剪辑带进了 1 个刻度（约 0.065 毫秒）的舍入误差；压字幕重新编码时，这个误差被对齐回了 30 帧/秒的标准格。画面和顺序都没变，但完全相等的比较判定为不同。属于"校验过严"。

## 4. 解决方案
- 新增 `_same_presentation(before, after)`：要求帧数相同、顺序一一对应，且每帧时间差 ≤ 1 毫秒（`PRESENTATION_TOLERANCE_S`）。一帧至少 33 毫秒（30 帧/秒），所以 1 毫秒的容差只吸收容器刻度的舍入，挪动一帧或丢一帧仍会被拒绝。
- 时长（≤1 毫秒）、帧数、零起点的检查保持不变。
- 这个改动不依赖模板，只依赖容器时间基与帧格，所以对任何参考、任何电影都成立。A、B 两条线做了相同的改动，避免影响两条线的对比。
- 这一条已经出的成片：直接取回服务器上已生成的字幕版 `final_subtitled.mp4`（sha256 63bb123e…，与服务器一致），作为 `交付_20261115/薛甄珠吵架_B线/薛甄珠吵架_B线_字幕版.mp4`。实测：3637 帧、1280×720、48k 立体声、字幕已烧进画面，符合新校验。没有为补字幕重跑整条任务。

## 5. 为什么不用其他方案
- 不校验帧时间，只比帧数：太松，帧挪动也会被放过。
- 拼接时强制把时间戳对齐到帧格：要改所有剪辑和拼接路径，改动面大，而且不能处理已经存在的中间文件。
- 重跑这一条来补字幕：会重做预览，可能重复花费配音费用，而且结果和直接取回字幕版相同。

## 6. 怎么验收
- 新增测试 `test_presentation_tick_residue.py`，共 3 项：
  - 用实测形态（第 3338 帧起滞后 1 个刻度）构造的帧时间，判定为同一画面。旧代码要求完全相等，按定义会失败。
  - 挪动一帧半帧时长，被拒绝。
  - 丢一帧，被拒绝。
- 服务器全量测试：A 线 217 项通过（原 214 项 + 3 项新测试），B 线 221 项通过（原 218 项 + 3 项新测试）。
- 用真实文件抽 5 帧人工查看，字幕清晰。

## 7. 量化数据
- 误差：299 / 3637 帧，每帧 1 个刻度，即 1/15360 秒 ≈ 0.065 毫秒。
- 修复前：这一条交付无字幕成片。修复后：新任务按新校验烧录字幕。
- 以往有多少成片被同一原因降级为无字幕：未统计。可以检查各交付目录 `检查记录.json` 里的 `subtitle_error` 字段。

## 8. 经验与后续
- 媒体时间戳的比较应该以"帧格"为单位，而不是比较容器刻度。
- 遗留：素材原带的字幕带只做了模糊处理，在成片中仍能隐约看到（A、B 线都有），和这次的问题无关，另行跟踪。
