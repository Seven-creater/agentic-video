## 1. 问题长什么样
赵德汉分镜有两个人：A 查办者、B 藏钱者。节拍 b2（B 说）、b3（A 说"你瞧瞧这是你家冰箱"）、b5（B 哭诉）。qfs_questions 回复里每个节拍的 `roles` 都是 `["A_boastful_villain"]`，casting 只给这一个角色选了 沈王爷 / 太郎。于是 b3 会去找沈王爷说话的镜头，查办者和藏钱者变成同一个人，对话无法在两人之间来回。

## 2. 怎么查出来的
新路线首个服务器任务跑到出题后，打印 storyboard.json 每格说话人和 questions.json 每个节拍的 speaker、roles、casting，发现说话人字母与 roles 不对应。

## 3. 根因
分镜路径的 QUESTIONS 提示词只写了"roles 与选角应对应该 speaker"，校验没有执行（e186def 版 src/omni_story/library/question_first.py validate_reply），模型照抄了提示词示例里的 `A_boastful_villain`。另外 `update_cast_anchors` 在单角色节拍拿不到选角提示时会把画面里任意演员设为锚点，同一影片人物仍可能被锚到两个字母上（GLM 审核时复现）。属于提示词与校验不一致（代码问题）。

## 4. 解决方案
分镜路径下：节拍 roles 由程序按分镜字母固定（说话人在前），模型的 roles 被覆盖并记录 `role_normalisations`；casting 只接受分镜字母为键，其他键丢弃并记录 `not_a_storyboard_role`；同一影片人物出现在两个字母下时只保留时间上先出现的字母，其余记录 `same_character_for_two_storyboard_roles`；分镜节拍不再使用"选角外演员兜底锚点"。提示词示例里的 `A_boastful_villain` 在分镜路径替换为 `A`。旧路径逐字节不变。规则只依赖分镜字母，对任何参考成立。

## 5. 为什么不用其他方案
- 只加强提示词：本次已经写了"应对应该 speaker"，模型仍未遵守。
- 违规时让模型修复：直连出题调用没有修复循环，违规即停机；roles 是机械字段，程序固定更稳。
- 同一人物两个字母时整体报错：会让本可用的选角整体停机；按时间先后保留并留痕更符合"程序修机械字段"的原则。

## 6. 怎么验收
新增测试：真实回复形态（全部 `A_boastful_villain`）→ roles 变成字母、该键被丢弃 → `no_valid_film_casting`；{"A":[Po],"B":[沈王爷]} 通过；两个字母都选沈王爷时只保留先出现的字母并记录；A、B 锚点互不串；旧路径提示词字节一致。全量测试失败集合等于基线，回放 0 条退化，fault_check 关键项为 0。服务器验证：sb_01_不烧心_11010232、sb_02_雪山救狐狸_11010232（791af39）出题结果待补。

## 7. 量化数据
修复前赵德汉 5 个节拍全部同一 role、1 个角色键；修复后应为 A、B 两个字母键（待服务器结果补）。

## 8. 经验与后续
抽象角色 id 这类机械字段不要交给模型抄写；凡是程序已知的结构都由程序填写，模型只做选择。
