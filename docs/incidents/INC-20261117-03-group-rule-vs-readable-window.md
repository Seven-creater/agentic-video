## 1. 问题长什么样
在 INC-20261117-02 修复后续跑。decide_1 这次是新发的请求，没有再被掐断，但三次回复依次报了这两个错：

- 第 1 次和第 2 次修复：`candidates[1] scene_group_id='cg_f6f8ea59911709bd' with window_ids=['vl_44914555277637ac', 'vl_79b18cc8b71dd8df'] does not equal one independently observed scene group. Use one of these groups exactly`
- 第 1 次修复：`candidates[1] uses windows without a usable subtitle-blind observation: ... still showing readable dialogue text ['vl_8913d79a6d643ccd']`

最后以 `model_protocol_repair_exhausted:material_scene_browser_decide_1` 停机。

## 2. 怎么查出来的
- 读三次的 `protocol_failure.json`：骑士组 cg_f6f8ea59911709bd 有 3 个窗口，第 3 个窗口 vl_8913d79a6d643ccd 精看时仍有可读对白字幕。
- GLM 第一次只交了 2 个干净窗口，被"必须等于整组"打回；改交 3 个，又被"不能用带字幕的窗口"打回；再改回 2 个，第三次失败。
- 定位到 `src/omni_story/library/material_browser.py` 的 `validate_finish`：分组检查要求 `set(ids)` 等于组内全部窗口；字幕检查要求候选不含 `subtitle_blind=False` 的窗口。一个组里只要有带字幕的窗口，这两条就不可能同时满足。
- 上一次运行（INC-20261117-02 那次）GLM 的回复里已经写着"第三段经复核仍有可读对白字幕，按规则不能入选，故本候选仅用两个干净窗口"，同样会被这条规则打回。

## 3. 根因
校验之间互相矛盾（代码问题）。场景组规则的本意是"不许跨组拼接，也不许挑一部分假装连续"，没有考虑组里有不能用的窗口。直接原因是骑士组里有 1 个窗口带可读字幕；根本原因是分组规则用了组内的全部窗口，而不是可以使用的窗口。

## 4. 解决方案
- 新增 `usable_group_windows(group)`：组里已经看过、而且没有可读字幕的窗口。
- 分组检查改为：候选必须等于某组的可用窗口；报错时列出每组的可用窗口，带字幕的窗口已经排除在外。
- 不能跨组合并、不能挑可用窗口的一部分，这两条约束保持不变。带字幕的窗口照样不能放进候选。
- 截取素材的 `grounded_candidate` 本来就只取候选里的窗口，不受影响。
- 这个规则只依赖窗口有没有字幕和分组结构，对任何模板都成立。

## 5. 为什么不用其他方案
- 删掉分组检查：会放过跨组拼接成的假连续场景。
- 在提示词里提醒 GLM：它已经主动按"排除字幕窗口"作答了，是校验在打回它。改提示词治不了本。
- 把带字幕的窗口拆成单独一组：要改连续性复核，而且会让组的含义变得混乱。

## 6. 怎么验收
- 新增 `test_group_usable_windows.py`，共 3 项：
  - 带字幕窗口的组，用其余窗口作为候选可以通过；
  - 带字幕的窗口仍然不能放进候选；
  - 只用可用窗口的一部分仍被拒绝，报错里给出准确的可选窗口。
- `test_browser_comparison.py` 只把报错文字的正则同步成新文字，测的含义（不能跨组合并）不变。
- 服务器全量测试：A 线 224 项、B 线 228 项全部通过。
- 真实续跑：从 001712 续跑，结果待补。

## 7. 量化数据
- 浪费：3 次 decide 调用，约 9 分钟。
- 涉及的组：3 个窗口里有 1 个带可读字幕。

## 8. 经验与后续
- 新增校验规则时，要检查它和已有规则能不能同时满足；最好对每种错误提示都构造一个"按提示改了就能通过"的用例。
