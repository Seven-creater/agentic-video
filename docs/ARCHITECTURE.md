# 架构

系统分为共享素材知识、单条创作和批量执行三部分。模型负责创作选择，程序负责来源、时间、实际执行和状态记录。

## 可复用视觉库

`visual_indexer.py`按时间窗口观察素材，`visual_library.py`保存与检索已收记录。每条记录包含来源 SHA、原片时间范围、原请求和回复绑定、观察方式及限制。

记录关注实际画面：人物外形与可区分性、动作和状态变化、物件、空间关系、反应与可剪范围。可能适配的用途作为条件性线索保存，不当作已经发生的事实。人物稳定身份需有实际外形证据，不能把一群人或相同动物种类当成同一个角色。

参考理解将主旨拆成表达需求；检索为同一需求提供多种视觉候选。例如“拒绝”可以由对白、推回物件或听者反应承担。已收记录先复用，仅对关键缺项、动作边界或身份不确定处局部复看，候选足够便停止扩展。

## 单条创作

| 阶段 | 主要模块 | 职责 |
| --- | --- | --- |
| 热点获取 | `discovery/hot_capture.py` | 原始API缓存、多作者作品、真实声画比较、参考来源回执 |
| 后台入口 | `library/hot_pipeline.py`、`server_cli.py` | 配置、来源绑定、作业启动与结果输出 |
| 粗剪 | `pipeline.py`、`story_context.py` | 参考表达、检索、人物与故事段落、视觉覆盖、完整音频草稿 |
| 音频 | `tts.py`、`audio_draft.py`、`visual_audio.py`、`audio_render.py` | 已收TTS复用、实际PCM时长、排时、混音与实际声画审核 |
| 精剪 | `clean_chain.py`、`story_finecut.py` | 以真实粗剪为输入，局部补看、关键变化、编辑表、渲染与内容判断 |
| 媒体执行 | `media.py`、`render.py` | 真实时间戳、裁切、变速、停留、来源校验 |

故事计划区分镜头的叙事功能和声音关系。角色建立后，其声音可以继续覆盖动作、反应、物件特写；不要求每句话对应说话者正面镜头，也不要求固定镜头比例。

参考决定声音形式。对白、旁白、混合和无语音分别处理，不能把角色对白统一改成第三人称讲述。文稿在粗剪规划时建立；TTS按实际音频长度排时，精剪尽量复用，最终再加字幕。

## 批量执行

`hot_batch.py`是一个有限批次协调器，沿用`server_jobs.py`启动独立编辑子作业，没有新建常驻队列服务或自动重启系统。

1. 串行获取共享热点缓存，从本批已选主题和参考SHA中去重。
2. 收到一份适合的参考后，立即启动独立编辑子进程；采集下一份参考时，已启动的编辑可继续等待模型或处理媒体。
3. 按用户并发上限、内存预算和未用磁盘预留决定是否接入下一条。
4. FFmpeg使用跨进程文件锁限流，CPU线程和单文件写入受限。
5. 批次逐条收敛，结果分别保存，不混合成功、候选与失败状态。

配置上限是32条编辑线，默认2条；实际容量取资源限制后的更小值。为避免多个协调器对同一磁盘重复预留，同一运行根目录只允许一个批次协调器。每条模型调用仍独立按阶段执行。

## 状态与复用

请求在发送前记账；已收原回复保存并按SHA复用。结果未知时停止该分支，不通过换目录或新提示自动重放。共享采集出现未知会阻止后续采集；批次编辑出现未知时停止新增任务，并保留同批其他已启动作业的结果。

正常退出仅代表程序执行结束。`content_delivery_ready`、具体内容状态和原负面审核一起保存；`candidate_needs_revision`不能冒充通过。当前模块中保留少量运行依赖的兼容校验，旧独立恢复启动器不属于公开入口。
