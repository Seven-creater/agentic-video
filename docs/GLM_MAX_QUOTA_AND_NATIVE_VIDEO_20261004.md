# Max 套餐额度与不经过 MCP 的视频理解

核对日期：2026-10-04，Asia/Shanghai。用户确认订阅国内 GLM Coding Plan **Max**。
用户提及“可能每月 400 次 MCP”，但未给出该额度项目的名称或账户用量记录，因此不能将它当作已验证账户限制。
本轮只读取官方公开文档和本地代码，没有发送模型请求、查询私有账单或切换运行提供方。

## 公开规则与账户事实

[官方 FAQ](https://docs.bigmodel.cn/cn/coding-plan/faq) 当前明确模型与 MCP 共享套餐额度。
[套餐用量说明](https://docs.bigmodel.cn/cn/coding-plan/overview) 的个人 Max 为每 5 小时 28,000 积分、
每周 140,000 积分；公开规则没有把视觉理解列为独立的每月 400 次项目。
这些是目前公开的新规则，不能替代用户账户可能存在的老版权益、剩余额度或实际费用明细。
[老用户权益说明](https://docs.bigmodel.cn/cn/coding-plan/notice/usage-revision) 明确保留V1/V2既有额度规则；
该页列出的V2 Max为每5小时约1600 prompts、每周约8000 prompts。prompts并不等同本项目的HTTP请求计数。
仅知道“Max”还不足以判断账户是积分制还是旧版；两种公开口径都不能据此证实视觉每月400次。

用量说明将 GLM-5.3-Flash 与视觉理解 MCP 列在同一模型行，抵扣系数为输入 2.3、缓存输入 0.56、
输出 8；模型积分按输入／缓存／输出 token 折算。联网搜索、网页读取和开源仓库另列按工具次数的抵扣规则。
因此不能把所有 MCP 统称为同一种每月次数池，也不能把本项目的 79 次内部调用当作套餐已消耗 79/400。
该任务有 78 个已知回复和一个结果不明请求；未知账单不能当零，实际抵扣看账户明细。

当前 [Flash 夜间活动](https://docs.bigmodel.cn/cn/coding-plan/notice/event-glm-5.3-flash) 的免费条件为
ZCode／AutoClaw、每日 23:00 至次日 09:00、活动截至 2026-10-07；其他支持的 Agent 是额度翻倍。
这不是当前 Codex 会话官方视觉 MCP 无限免费的证据，且仍有活动前额度耗尽等规则。

## 可以不使用 MCP，但接入与计费分开判断

[GLM-5.3-Flash 官方模型页](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash) 明确模型原生支持
视频、图片、文本和文件，并提供模型 API。视频能力不依赖 MCP 协议本身。

| 接入 | 是否必须经过视觉 MCP | 额度与限制 |
| --- | --- | --- |
| 当前 Codex 会话连接官方视觉 MCP | 当前项目实现需要 | 保留既有套餐接入；新公开规则与模型共享积分，账户实际规则待核验 |
| 官方支持的 Agent 使用 GLM 原生视觉 | 原生输入本身可不经过该 MCP | 可以继续用 Coding Plan；具体客户端的视频输入与自动化接口仍需实测 |
| 项目 Python 直接接标准模型 API | 不需要 | 标准 API 单独计费，不能承诺使用 Max 订阅抵扣 |

官方 FAQ 明确自建应用／机器人等 API 集成应使用标准 API，Coding Plan 限定在
[指定工具与环境](https://docs.bigmodel.cn/cn/coding-plan/tool/others) 内。
不能只去掉 MCP 包、复制其内部请求，便声称获得套餐外独立 Python 服务或绕过额度。
官方支持列表含 ZCode、Codex、OpenCode 等；原生视觉的订阅接入不等于任意 Python 请求均可使用套餐。

若优先节省额外支出，先核验账户规则以及支持的 Agent 的原生视频入口；若优先独立 Python 自动化，
标准 API 是清晰的可选路线，但需先确认费用与实际视频协议。切换应另记提供方、媒体 SHA、模型版本、
协议、原始回复和计费边界，不能把旧 MCP 结果重新标为新路线质量证据。

## 用户最新预算指令

用户明确要求取消程序自设的 80 次请求限制，检查停滞而非进行无意义循环。
旧输入锁、79 条账本和旧 80 上限仍作为历史保留；新执行不能将其视为套餐限额或停止重新剪辑的理由。
此前 CPU 提案的 44 次新增请求也不再作为用户要求的硬上限。

新执行策略拟为无数字请求总上限、一次有序剪辑流程、每阶段至多一次格式修复。
超时保留原在途请求，未知结果不重放；同一步没有新证据／计划／输出时不改名反复提交。
平台限额、认证错误、协议修复耗尽和无进展均应停止并留下诊断；模型拒绝质量通过不被改成 pass。
现有 EDL 最多 32 段是结构执行限制，不是套餐调用限制。

这些是用户授权范围和当前工程策略说明。本轮没有激活增量执行授权或发送新模型调用；
不因公开额度大就擅自使用标准按量 API，也不自动替换被冻结路线。
