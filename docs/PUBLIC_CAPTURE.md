# 服务器公开网页采集

`--capture-source public_browser` 通过服务器上的正常 Chromium 会话读取抖音公开热点页及相关推荐，保留原始 HTTP 响应、哈希和实际作者、发布时间。榜单使用实际 `active_time`；相关推荐只是候选，不代表平台证明它们属于同一模板。模板结论仍须通过三位近期独立作者的完整视频声画比较及素材库适配审核。

此来源不读取 Wellbyte Key，不发送 Wellbyte 请求，不改写其失败或未决台账。原 Wellbyte 入口的未知调用保护保持原样；任一来源、任一小时目录里的未决模型调用仍阻止新的公开来源模型调用。新来源也保留历史未知素材排除、下载预算、批次去重及质量门槛。

服务器需要 `.[capture]` 对应的 Playwright 1.64.0、已验证的 Chromium headless shell，以及正常可用的浏览器沙箱。本次部署的浏览器路径为 `/opt/omni-public-browser-1248/chrome-headless-shell-linux64/chrome-headless-shell`。浏览器文件由 root 持有，精确路径 AppArmor 配置允许它创建沙箱所需的 user namespace；全局限制仍为 1。部署收据记录原始官方归档与可执行文件哈希。

公开浏览器入口目前针对已配置上述路径与沙箱的 Linux 服务器；普通安装不会自动安装或配置该浏览器，其他环境需要先完成相同的系统部署。仅安装 Python 的 `capture` extra 不足以直接运行此入口。

在原批次完成数量和未决模型调用已经核对后，使用正常批次入口并明确选择来源：

```sh
omni-hot-video --home /home/ubuntu/apps/agentic-video batch \
  --capture-source public_browser --count 5 --concurrency 5
```

实际生产输出仍写入 `shared/jobs`；`shared/runs` 是保留素材库 provenance 的兼容链接。配置中的每路内存、磁盘和渲染预算继续控制实际并发。

`public_calls.json` 的 `received` 行对应实际收到的公开 HTTP 字节；`derived` 行是绑定原始响应哈希的字段规范化，不是新的 API 成功回执。参考视频、审核通过、启动器退出 0 都不等于成片交付，最终以真实批次结果及成片验证为准。出现验证码时停止该路径，不自动处理验证码、注入登录态或生成伪造签名。

网页响应在 `requestfinished` 后读取。导航导致正文不可用时保留 transport 记录；实际浏览器 DOM 快照单独标为 `derived/browser_dom_snapshot`，仍须精确匹配 `hotInfo.hotId`。已收到的完整正文优先在本地解析。候选排序保留主视频在首位，其余优先考虑平台 `hot_list` 中与目标热点明确相同的 ID，其后优先采用与主视频相同的非空音乐 ID，再按时长排序。音乐相同只是召回线索，不代替同款判定。

普通相关推荐响应中的原生热点标签可作为单独的 `extra_trends` 候选流。标签必须绑定原始响应 SHA，热点 ID、名称和栏目须与原生 `extra` 字段一致，热度为正；响应时间与标签请求时间都须在新鲜度窗口内且相差不超过 300 秒。非零到期时间必须尚未到期；零表示未提供期限。证据记录在 `candidate_discovery`，标签观测时间不冒充主榜更新时间，实际主榜时间校验保持不变。主榜和新增候选保留各自排序、交错进入同一候选数量上限，后续仍检查当前热点页精确绑定、主视频新鲜度、三位独立作者、完整声画和素材库适配。同一个模板的不同热点别名仍不能算作五个不同热点。

原生标签指向的作品可以通过正常 `/video/{native_id}` 页面核验，而不要求主榜专用 `/hot/{tid}` 必须提供代表作。原始 related 收据中的标签先精确绑定热点及 native ID，再要求新收到的 HTTP200 视频文档包含相同路由 ID；页面正常发起的详情请求及响应 ID 也须相同，且作者和发布时间与原始记录一致。只收以该 native ID 为 parent 的真实 related 响应。仅有 DOM 快照不满足这个入口；旧 `/hot` 不可用记录和新 `native_topic_*` 收据分别保留。该过程是两段独立来源绑定，视频页本身不证明热点归属。

完整声画审核明确收到 HTTP200、所有其他字段及成员时间都通过校验，但只缺少 `limitations` 键时，可进行一次独立的格式纠正审核。原始回复和失败文件保留；`*_protocol_correction_v1/audio_review` 绑定原 ledger、response、失败文件及完整比较视频的 SHA，仍被全局未决调用检查覆盖。新的审核须重新作出真实内容判断；负面结论、其他格式错误、HTTP 错误及纠正再次失败均不因此获得额外请求。已有失败文件与原 ledger/response 不一致时立即停止。

已收到 `same_template=true` 但素材适配未通过的结果时，可使用该回复中的可见动作及改编锚点补做本地素材检索；只纳入视觉事实的多字命中，保留全部限制和不确定性。出现新 observation 才能进行一次新的完整 AV 适配评估，原负面结果仍保留。原 ledger 旁的 `library_recall_once_v1.json` 在请求前固定原始 SHA、输入媒体和唯一候选列表；后续运行复用该列表及其审核缓存，不因又找到其他素材重复请求。这次评估不再追加格式纠正请求，失败仍然拒绝。

比较代理目录及来源清单绑定有序的视频 ID 和完整 SHA256。旧代理不会作为新样本的输入；只有从当前源文件重新生成的比较代理与旧代理字节完全相同、提示词也完全相同时，才复用原模型请求路径及收到的响应。原始收据保持原样。

同一批次需要复用已验证的榜单时，可指定隐藏参数 `--public-cache-root`，只接受 `shared/data/hot_references/public_*` 内已有的公开响应台账；实际榜单时间仍须满足 `--freshness-hours`，所有全局未决模型保护继续执行。这用于保留本批次来源与响应复用，不创建新小时目录来绕过限制。

完整比较视频的 Base64 若达到 10MB，使用百炼官方、同账号同模型绑定的临时上传通道（单文件最多 256MiB，48 小时自动失效），而非截短、加速或静音。仅大陆官方端点可用。提交前仍写入原文件哈希、完整时长、传输配置和 submitted 台账；结果未知则停止且不重发，已收到的审核可在本地缓存复用。临时空间适用于本次有界验证，长期生产应配置官方建议的自有 OSS。
