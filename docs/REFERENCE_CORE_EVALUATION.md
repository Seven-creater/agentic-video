# 以核心主旨为目标的四类评测

四类题统一测：能否识别并运用视频表达的核心观点、价值取向、态度或情感。保留实际情节作为证据，不把换人物、道具或场景当作理解错误；也不把所有模板硬解释成道德说教。

## 1. 完整视频理解

输入整条干净参考，由原生产理解模块产出原始 theme / intended_takeaway 等结果。评价三个方面的明确表达：主要矛盾或情感对象；态度与选择方向；核心含义及其作用。要素来自逐模板标注，不机械地要求所有视频都有相同三段故事。

例如，不烧心的标准聚焦：眼前小利与原则的冲突；宁可承担损失也不坏规矩；体现可靠和良心。冲奶粉、人物身份、奶量只用来佐证。输出包含这些细节不会被扣分，但只有细节、没有对应含义不能算完整理解。

## 2. 前缀推测整片主旨

只给同一视频前几秒实际裁切后的声画，通过原生产理解入口单独处理。不能携带整片理解、另一份同模板完整理解、模板名称、搜索解释或标准答案。完整输入与前缀输入是两种独立条件，单独保存回执。

回答这个视频大致会表达什么、可能持什么态度、依据是什么，允许列出合理的多种可能和不确定性。不要求还原人物和逐步动作。前缀已经点题、只隐含冲突和信息不足三种情况分别记录；不会把无法唯一推断的主旨当成唯一必答。

不烧心：根据省成本的诱惑和犹豫，预测围绕短期得失与良心规矩的抉择；不要求预测谁拿起奶瓶、具体毫升或确切对白。另标记是否正确判断最终价值方向，避免只猜中“大概讲原则”就声称完全正确。

## 3. 长故事中寻找相同主旨

根据原模块的完整理解，在合成长故事中找出表达同类价值选择或情感关系的段落，并解释对应关系。人物和行业可以完全不同。

不烧心的正确对应可以是店主宁可少赚也坚持用料；干扰项可以是同样冲奶粉却为省钱降低标准，或表面说守规矩、实际趋利的情节。必须同时区分“表面像但主旨相反”和“表面不同但主旨相同”。程序按所选ID提取原文，不要求模型手抄。

## 4. 纯BGM识别模板及其主旨

用户已进一步明确：有些模板有固定BGM，听背景音乐就能辨认关联模板。这一题优先测这种音乐线索；不要求音乐单独推出具体伦理观点，也不统一要求阶段卡点。

从干净未见视频中提取真实纯BGM片段，隐藏对白、画面、模板名、片段来源时间及标准答案。程序与已登记参考的实际背景乐比较，返回关联参考，并检索该参考由原生产理解模块生成的主旨。

分开报告：①BGM匹配正确率（多个模板共曲时保留多解及覆盖率）；②匹配后返回的原理解是否表达了对应模板的核心主旨。不得把人工写好的模板含义写入查询答案，也不能识别出音乐就宣布理解正确。

已将不烧心目录下全部10条原音轨交给Qwen进行无画面、无名称的音频盲听初筛；这属于数据核验，不是正式音乐成绩。初筛结果及其局限见运行目录的《BGM核验与测评记录.md》。核验同曲、变奏及异曲时不能只信BGM标签；这只是核对示例。其他模板各自研究主旨、声音和干净实例，不套用不烧心的价值观。

BGM识别得到的是已登记模板的音乐关联，不保证任意使用同曲的改编视频都表达同一立场。比如同曲可以用于反讽；这类输入记录主旨歧义，不因听到了同曲就断言未见画面中的实际价值选择。正式样本在看被测输出之前核验主题一致性。

音轨提取不等于人声分离：初筛可听混合音轨，但正式题必须有真实无对白窗口或经核验的分离BGM。不能依赖原片对白、演员音色或同一配音完成识别。音乐辨识不足、曲目跨模板共用或声音不合格时记录明确原因。

## 统计与边界

沿用文稿对应题型的命中、部分、遗漏和矛盾统计；不新增四类加权总分。前缀题改为主旨与价值取向吻合，不再用动作事件F1代表主旨理解。故事报告首选和引用范围；音乐报告纯BGM匹配率、检索主旨的吻合情况及不适用／多解覆盖。

10条参考各建4项，40项保留在计划中。有效题覆盖率和成绩同时给出。人工未确认的主题和答案标为模型辅助；之前只确认粉衣人跪地的动作不算确认模板主旨。新方案与旧叙事评测分开，不拼接成绩。

生产主分支和现有线上current继续冻结；音乐修复在 codex/reference-music-understanding，评测在 codex/reference-understanding-eval。新版本分别推送、部署和记录SHA，预算仍为原累计100元上限。

## 不把一种主旨套给全部模板

| 模板示例 | 应理解的核心内容 | 不以这些表层细节代替 |
|---|---|---|
| 不烧心 | 不为小利破坏原则与良心 | 谁冲奶粉、冲多少毫升 |
| 马冬梅 | 反复表达仍无法有效沟通的无奈 | 谁问路、名字是哪三个字 |
| 见面 | 思念、相聚机会与陪伴的珍贵 | 几个男生吃哪种方便面 |
| 迈出第一步 | 勇气与行动比犹豫更能带来改变 | 穿什么鞋、骑车去了哪里 |
| 赵德汉藏钱 | 证据揭穿自我辩白和欲望掩饰 | 冰箱里具体放了多少钱或什么物品 |

每个主题仍须由所选具体视频实际支持。比如有些叶问二创讽刺逞强翻车，而原片表达实力自信；二者不能共用一个立场答案。情绪、讽刺、隐含爱意也属于内容，不要求都表达人品正直。

## 正式执行约束

前缀使用固定规则 min(5秒,参考时长/3)，通过冻结生产入口独立调用；仅补充“目前是前缀，请推测主旨并保留不确定性”的统一输入范围说明，不接收整片理解或主旨标签。该条件与完整输入分开存回执，不能把前缀的原始理解称为原完整输入成绩。

先完成各参考的原理解，再建立音乐检索库；纯音乐查询仍须通过实际无对白且有音乐的检查。无自然窗口时可尝试固定前8秒的双声道差分；它不保证分离成功，近单声道空结果及残余对白均排除。音乐分支SHA与理解生产版本分别固定。

出题模型也可能标反价值方向。正式运行前的数据核验可形成独立的模型辅助标注修订，必须保存原始标签、理由、源证据及哈希，不伪装成人工确认。正式评测一旦开始，不再修改标签、代码或提示词；收到的协议错误和未决状态保留在40项分母中。

## 资源适配与失败版本

首次正式运行发现原OpenCode外层加MCP、Python有超过每路1024MiB的情况，原始OOM事件和未决请求保留。评测侧新增`bound_mcp_runner.mjs`作为原provider的可执行入口注入：只连接冻结的`opencode_mcp.mjs`并调用其唯一的`execute({})`一次；原桥继续验证不可变任务、原提示词、原视频与官方MCP请求。它没有新的理解提示词，也不发起OpenCode调度模型调用，不伪造agent usage。原生产源码及线上启动配置不变，执行适配器版本在评测运行中单列。

长故事题由每模板的独立八段故事组成，不把其他九个模板的全部故事拼进每个问题。首轮实际400响应为1301内容检查拒绝，不推断为网络或token错误；隔离无关题材后仍拒绝的请求继续如实记录，不改写或编码受阻内容来绕过检查。

新版本可读取已有完整理解、前缀媒体及原回执；原未决来源保持隔离。不同版本的失败、有效覆盖和成绩分别报告，不能抹掉首轮OOM或将恢复过程称为一次无干预通过。

ASR隔离的父进程只安装轻量`WhisperModel`入口，不预先导入真实faster-whisper／CTranslate2；真实识别库只在短子进程载入。原权重、构造参数、转写参数及原始逐词返回保持一致。每路1024MiB限制继续生效，不能把识别进程移到计量之外。评测版本哈希同时包含Python与MJS适配器。
