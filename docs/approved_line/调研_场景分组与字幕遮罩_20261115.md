## 二、调研到的做法（均已读原文核实）

1. **NarraScene（arXiv 2608.28699）**：重新审视用于电影检索的场景分割。结论：
   - 现有方法的边界大多跟随“视觉显著变化”，会制造伪切点，把连续的叙事事件切碎。作为检索单元，它们并不比简单的等长切块好。
   - 提出三层变化：L1 时间、地点等视觉变化；L2 主要人物组合变化；L3 目标、互动或对话焦点变化。规定**有效边界必须包含 L3**，仅有 L1 或 L2 不算换场。
   - 零样本提示词中有“防过度切分（Macro over Micro）”规则：忽略小插曲、短暂打断和细小话题转折；服务于同一目标的短节拍合成一个场景；交叉剪辑但叙事目标相同也算一场。
   - 仅凭这套提示，Qwen3.5-9B 的 R@0.9 从现有最佳方法的 1.92 提升到 22.78。每次请求看 180 s 片段，并提供带时间戳的台词转写。
2. **LGSS（arXiv 2004.02678）**：把场景定义为“演员在同一物理环境中的活动与互动”，按片段、段落、整部电影三个层级逐级整合。
3. **BaSSL（arXiv 2201.05277）、ShotCoL（arXiv 2104.13537）**：用自监督学习“同场镜头相似、跨场镜头可区分”。需要训练，不适合直接接入，可作为背景参考。
4. **文本检索的上下文扩展**：LlamaIndex 官方 AutoMergingRetriever 先检出小片段，再按层级合并为更大的上下文。这印证了“相邻窗口补看”的方向。
5. **开源硬字幕工具**（video-subtitle-extractor / video-subtitle-remover）：批处理时要求视频分辨率和字幕区域一致，或给定字幕区域坐标；无区域时用 PP-OCR 做文字检测；去字幕后可用 LAMA 等算法修补画面，说明称该算法对动画效果最好。

注意：以上结论来自真人电影和检索问答任务，与“静音、遮字幕后剪辑选材”不完全相同。NarraScene 依赖台词转写，而我们刻意不给台词，叙事线索更少。因此必须用我们自己的真实素材验证，不能直接套用数字。

## 三、方案对比与建议

### A 场景分组（主要阻塞）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A1 建议** | 按 NarraScene 改写连续性复核的分组定义：同一地点、时间连续、围绕同一互动的一段算一场；镜头景别变化、特写或插入、反应镜头、背景特效、正反打、单个人物进出都不切分；只有换地点、时间跳跃，或互动目标改变时才切分。加入“防过度切分”规则。仍由 GLM 独立看片判定，程序不替它合并 | 直接针对伪切点；不放宽“不同组不能拼接”的防线 |
| A2 | 再加一次 GLM 调用，专门判断相邻两组是否同场 | 多一次调用；第一步定义不清时只是在补救，留作 A1 验证不达标时的备选 |
| A3 | 同一素材复核 2–3 次，取多数结果 | 调用成本翻倍，能降低波动但不能纠正错误定义，暂不采用 |
| 不采用 | 程序按文字描述自动合并相邻组 | 程序无法判断“灰背景近景”与“摊位”是否同地，等于编造事实 |
| 不采用 | 取消“一个候选只能是一组” | 会重新出现庭院、群像、吊桥被拼成一场对话的错片 |

**验收方式**：在真实素材上做小规模回归。
- 摊位素材（`5d4d` 加 `0aa53`、`5d4d` 单窗）各复核 3 次，要求每次都合为同一场；
- 至少 2 段确实换地点或换事件的素材（含 INC-27 庭院和吊桥类型），要求不被合并；
- 全部用真实 GLM 调用，记录分组结果。

### B 字幕遮罩

| 方案 | 做法 | 取舍 |
|---|---|---|
| **B1 建议** | 每部源片确定一次固定字幕带。用已有的 257 个定位结果统计这部片的字幕区域，再用少量抽帧核验；所有窗口使用同一字幕带，大模型逐窗定位只用于补充画面上方的额外文字 | 结果确定、各窗一致、不增加依赖；代价是画面底部约三成固定被遮，今天的遮罩本来也大多在这里 |
| B2 | 本地 OCR 逐帧检测字幕（PP-OCR） | 遮罩更贴合，但要新增依赖，在 CPU 受限的服务器上每窗约多花几十秒（推断，未测）。可作为 B1 之后的升级 |
| B3 | 遮罩改为画面修补（LAMA） | 解决“黑块碰到脸”的观感问题，但较慢，且可能补出原片没有的内容，影响画面事实，本轮不做 |
| 不采用 | 放宽“不能有可读字幕”的规则 | 原台词会带偏 GLM 的静音判断，违背用户要求的“静音遮字幕看片” |

### C 素材容量提前检查（工程问题，无需调研）
在锁定角色之前、配音合成之前检查两件事：素材总时长与对白需要是否匹配；每个说话角色是否有能单独认出的首次亮相镜头。任何一项不足就先补看相邻窗口或换候选；仍不足则在配音前停止并说明原因。首次亮相规则不放宽，也不靠循环同一镜头硬撑。

### D 补看额度
相邻窗口补看额度优先给排名第一的候选。

### E 流程
修复后用同一固定版本从参考视频冷启动，中途不改代码。只有这样跑通，才能称“独立产出”。

## 四、建议执行顺序
