# 停机通用治理（2026-11-17）

用户要求：后面有成千上万的参考模板，不可能每条都针对性修复。所有排查出的停机原因都要用通用办法解决，不能针对某个模板。

## 1. 盘点依据

服务器上全部 `trials/**/run_outcome.json` 里一共有 120 次停机记录。去掉主动叫停（`official_MCP_connection_stopped`，39 次）和运维类停机后，按原因分为四类：

| 类别 | 次数 | 主要报错 |
|---|---|---|
| A. 格式修复用完 | 约 17 | `model_protocol_repair_exhausted:`，涉及场景切分、逐窗看片、认人、挑素材、选角、改编计划、参考转写和复核 |
| B. 接口或守卫拒绝 | 约 15 | `opencode_vision_job_failed_no_retry`（8 次，**全部是我们自己的守卫拦下的**：`stage_duplicate_or_not_permitted` 是阶段名不在白名单，`retry_or_budget_blocked` 是同样的请求体第二次发送）、`provider_content_rejected`/`provider_request_rejected`、Qwen 返回 400 |
| C. 模型回复不合规时没走修复、直接抛错 | 约 12 | 说话人不在已知名单（4 次）、KeyError、IndexError |
| D. 素材或原声不够就停 | 约 12 | `cast_expansion_no_new_video_evidence`（5 次）、`cast_material_gap_after_expansions`、`joint_coverage_insufficient`、`browser_followup_material_gap`、原声不足 |

格式修复用完时最后一次被打回的原因，有几种固定模式：
- JSON 语法错误；
- 字段要求是文字，写成了对象；
- 规则互相矛盾（场景组 vs 带字幕窗口、按占比分配的预算）；
- 长列表要求逐条交回所有编号，模型漏几条就整体打回；
- 模型编造了不存在的编号。

## 2. 通用规则

1. **结果不确定绝不重发**（不变）：已付费、结果未知的请求，照旧停机。
2. **明确失败可以重问**：接口明确报错、而且没有产出任何结果时（比如 Qwen 的 `InternalError.Algo`），换一个请求重问一次，绝不重发同一个请求体。
3. **接口拒绝某个素材**（内容审核、请求被拒、输出被掐断），抛出 `ProviderRefused`：
   - 能少用这个素材的调用方（一个窗口、一对人物、一段片段），就把它剔除后继续；
   - 不能少的调用方，才停机。
4. **看片、认人这类观察步骤修复用完**，抛出 `ReplyUnusable`，调用方把这一项当成"不确定"：
   - 不新增任何事实，不认任何说话人，判断人物是否相同时一律按"不能确定是不同的人"处理；
   - 然后继续，不停机。

   决策类步骤（挑素材、选角、改编计划、写剧本）修复用完，照旧停机，由第 6 条的兜底机制保证尽量不走到这一步。
5. **调用层统一兜底**：
   - 守卫按命名规则自动允许新阶段，不再逐个登记；
   - 所有调用路径先复用"同样的请求已收到的回复"；
   - JSON 解析容错：字符串里原样的换行等控制字符、对象后面多余的文字、代码块包裹都能解析。
6. **素材不够不再停机**（用户 11-17 定）：
   - 补画面找不到新证据，就换下一个候选场景；
   - 候选全部用完，按画面里实际有的人物改编角色；
   - 原声不够，就用预设音色（用户已同意）。
7. **长列表由程序负责**：编号和顺序由程序补齐，模型漏掉的只追问漏掉的那几条，不让它整份重交。

质量底线不变：
- 不同角色必须由不同的人演；
- 观众要能认出是谁在说话；
- 画面和台词不能矛盾；
- 不能声称看见了没发生的动作。
