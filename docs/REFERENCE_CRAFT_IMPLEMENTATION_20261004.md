# GLM 剪辑知识与自主参考复看

这一步将通用剪辑知识实际送入 GLM 的视觉请求，让它自主决定复看问题、范围和所需知识卡。
它是参考分析的新增验证阶段，不是一次新的电影剪辑或成片质量验收。
相关资料与适用边界见 [调研记录](REFERENCE_EDITING_SKILL_RESEARCH_20261004.md)。

## 已实现的流程

1. 读取整个固定参考的正常速度、12 fps 分析代理；同时输入通用手册和知识卡目录。
2. GLM 报告全片可见信息，自主选择最多三个、各不超过 12 秒的连续复看窗口、具体问题和知识卡。
   可以选择零个窗口或零张卡；没有指定人物、剧情答案、示例秒数或必须出现的技巧。
3. 执行器从最早起点到最晚终点制作一个 30 fps 连续包络代理，保留正常播放速度和源时间映射。
   所选窗口都包含在这个实际媒体内；跨度可能覆盖整条参考。它没有人为拼接、转场或减速。
   若模型没有选择局部范围，第二阶段仍使用全片。
4. GLM 获取实际连续媒体、自己的问题以及选中的知识卡，区分可见证据、手法解释、作用推测、
   替代解释和未解决问题，并提出素材条件、执行操作和输出核验条件。
5. 将选片、实际媒体 lineage、两阶段原始请求／响应与知识版本绑定到新增结果，保存规划交接字段。
   旧剧本、EDL、参考解释、失败评价和成片不改写。

官方 MCP 的视频入口没有可控的云端采样参数。30 fps 只描述输入代理，不能证明模型逐帧观看。
`coverage` 是模型报告的时间分段，不是观看仪表。准确参考速度没有原始拍摄片段对照时保持 `null`；
声画节拍状态保持 `unverified`。模型给出的 `supported` 不是人类真值。

## 知识与能力

项目内手册为 [SKILL.md](../omni_story/library/craft_knowledge/SKILL.md)，另有八张小卡：时间省略、
动作匹配、动作与反应、速度变化、镜长停留、定格与回放、转场构图、声画边界。
它们借鉴 Yale、VEU-Bench 和 Adobe 的公开资料；工作流和操作条件是本项目的组合设计，
没有声称这些文献验证了 GLM 的成片能力。

这是 GLM 请求实际读取的项目知识，不是安装到 Codex 后假定 GLM 自动获得的技能。
首次分配时将全部知识文件复制到运行记录，保存版本和 SHA；恢复使用该快照，不用后来改写的卡。
Python 包配置包含这些数据文件。

执行器支持不连续片段、硬切、每片段 0.5–2 恒定倍速、尾帧定格、居中裁切和静态文字。
平滑连续速度坡道、光流补帧、倒放、复杂转场、动态重构图和 J/L cut 仍未实现。
本阶段提出执行建议，但没有新 EDL 或实际输出验证。未来剪辑必须再次核对真实库内素材，
把操作落到 EDL，并对实际视频静音盲读及逐项审核；不能把交接 JSON 当作已经完成迁移。

连接命令仍见 [本地指南](REFERENCE_LIBRARY_LOCAL_RUN.md)。


只接受已存在的任务。固定参考、电影文件集合、SHA 和原输入锁必须匹配。
这次从原任务 76/80 次请求开始，预留最多四次：两个阶段，每阶段最多一次协议修复。
没有额外库内精看窗口或第五次渲染。首个不明请求 004 继续保留，不能重放。

新增记录：

- `artifacts/reference_craft_allocation_001.json`：一次性分配、原调用和受保护文件。
- `artifacts/reference_craft_observation_v1/knowledge/`：本次知识快照。
- `calls/glm_*_craft_scan*/`、`calls/glm_*_craft_inspect*/`：原始请求、回答及校验状态。
- `artifacts/reference_craft_result_001.json`：成功完成协议后的新增观察与规划交接。
- `artifacts/reference_craft_failure_*.json`：失败证据；失败不伪造为结果。

完成后恢复会校验调用、响应、解析内容、代理 SHA、lineage、知识快照及历史文件，然后返回缓存，
无需模型连接或新增请求。旧 `--continue-semantic` 入口也保留其原结果和原用量，避免将新观察
调用累加到旧成片记录后覆盖它。结果不明时不自动重放。

## 验证边界

测试使用真实 FFmpeg 媒体与生产文件队列，仅模型回答是夹具。覆盖范围映射、未知知识卡、越界
证据、未实现效果、准确倍速伪称、预算不足、两阶段修复上限、停止连接后的恢复和历史保护。
这些测试验证执行与溯源，不证明参考理解或剪辑质量。

本地全量回归 **528 项通过、2 项因冻结发现线依赖缺失跳过**（463.45 秒）。
随后补充四个防篡改用例，并再次执行新增模块，共 15 项通过（14.61 秒）；该模块与全量测试有重叠，
不能直接相加。wheel 打包实测包含全部 10 个知识文件。不得以手法术语增多代替质量改善。

GLM 自选 `14–18`、`18–21.933333` 秒，选读转场构图、时间省略和停留三张卡。
第二次实际输入为 `14–21.933333` 秒连续代理。有效回答提出三项模型观察：
现状与童年照片硬切对比、生活信息的时间省略、字幕阅读所需的镜头停留。
准确参考速度保持 `null`，声画节奏仍为 `unverified`。

协议完成不代表语义全面通过。此次自主复看偏向结尾，未细看比赛段的准备、关键行动、结果
和反应如何被组织成短叙事，也未验证加速、慢放或动作匹配。不能说这些手法不存在，也不能
说它已经掌握它们。模型仍将若干字幕和静态结果描述成实际动作：例如原参考18秒的抽取帧
显示拥抱及“全国冠军”文字，19秒显示《我的父亲》手写文章；单帧不能证明用嘴／脚完成动作，
也不能确认文章作者或写作过程。该抽查不是全段反证，保留这一证据边界。

模型还自称“1fps采样”，这不是提供方测量。记录只确认实际输入代理30fps，云端采样未知。
独立执行器抽查记录及图像留在 `artifacts/reference_craft_observation_v1/`，没有送给 GLM 或改写其回答。
新增规划交接保留模型建议与不确定性，不能当作经过独立证实的剪辑约束。

因此，这轮确认的是 **知识实际送达、自主选择与复看执行、证据绑定和恢复**；
整条参考剪法理解、在电影素材中的迁移及成片观看效果仍未验证。
后续观察策略需要围绕各段的信息变化与未核验手法自动提出问题，避免只围绕题材和字幕复看；
同时记录每项含义来自画面、文字还是推断。具体区间仍应由模型选择，而非硬写此前示例秒数。
