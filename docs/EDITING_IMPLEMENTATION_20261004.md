# 参考剪法实施与离线核验（2026-10-04）

本次把[剪法调研](EDITING_TECHNIQUE_RESEARCH_20261004.md)落实为可执行的模型协议、时间证据和渲染能力。
工程验证使用真实 FFmpeg 合成媒体与假 MCP 回答，不代表 GLM 已在真实电影上掌握这些剪法。
原真实运行仍选择 `render_0/final.mp4`，主旨 partial、剪法 partial、人物连续性 pass。

## 新执行协议

`reference_methods_to_operations_v2` 通过 `omni-library --editing-v2` 启用，仅适用于尚无计划的任务。
政策单独追加到原 state 的 artifact 历史，不改输入锁、基础政策或请求、精看、渲染预算。
恢复读取带 SHA 校验的政策记录；后续命令不重复加该参数也继续使用原协议。
已有 `plan_*` 的旧任务不能用此参数改写历史，不能用新目录重置相同任务的预算。

流程为：

1. GLM 观看固定参考，逐项补充原 `editing_methods` 的形式、表达作用、素材条件、观察范围、核验办法和音频依赖。
2. 根据这些要求检索并精看真实候选。细看片段附带代理文件的图像变化时间线；代理秒点和原电影原生帧证据明确分开。GLM 记录实际景别、动作方向／阶段、反应关系等可见条件，以及独立的潜在用途解释。
3. GLM 在 `editing_bindings` 中将每种剪法绑定到实际 EDL 片段、顺序和操作；不支持的方法必须保留并说明 unavailable/unverifiable。
4. `candidate_dispositions` 逐项解释所有已看窗口的采用或弃用，且与 EDL 一致；程序不替模型选片。
5. 渲染后先隐藏计划进行盲读，再逐项核验实际成片的形式和表达作用，使用输出秒点证据。

结构校验只证明引用、来源和时间合法，不能证明方法有效。v2 不会因“主旨与连续性通过”而忽略剪法缺项提前结束。
视觉 MCP 未审听音频；依赖声音的方法必须保留 unverifiable，不能给出完整剪法 pass。

新增 `editing_reference_v2.json`、`editing_evidence_<轮次>.json`，原请求与回复继续保留在 `calls/`。
新增参考实施分析通常多一次模型请求，格式修复仍至多一次，全部计入原请求预算。

## 实际渲染能力

- `segments.freeze_tail_s`：0–10 秒。播放所选原片范围后复制最后真实输出帧；源声音在尾部静音，参考声音按既有音频模式继续。
- `segments.caption`：GLM 自主写静态文字，选择 top/center/bottom、12–120 像素字号及该片段输出局部起止秒数。文字最多 300 字符，可自行换行。
- 文字证据必须关联同一已看窗口、与所选原片范围相交的事件；结构验证不保证文字含义成立。
- 字体由本地控制，文字以 UTF-8 文件交给 FFmpeg，禁用表达式展开；不接收模型指定字体路径或执行代码。
- 本地使用实际字体测量字形、换行和描边，要求完整位于画布 8% 安全边距内。越界进入已有的一次模型协议修复，由 GLM 自主缩小字号或换行；程序不重写文字。
- 新计划的总时长含定格，按实际输出帧舍入仍须不超过 180 秒；字幕也必须覆盖至少一帧且不越界。

无新增操作的旧计划保持 `library_render_v1` 编译结构与缓存。实际使用定格或字幕时使用 `library_render_v2`，
记录 motion/freeze 帧数、请求与实际字幕时间、字体 SHA 和来源范围。
定格记录不伪造最后原片帧的精确 PTS；字幕或定格不能创造新的事件证据。
J/L cut、声音分离、节拍对齐和完整音频审听仍未实现。

## 对当前真实运行的离线检查

```powershell
.\.venv-library\Scripts\omni-library.exe --reference "data\ref\video.mp4" --library "data\videos" --output "runs\library_reference_20261004" --audit-editing
```

此入口只用 CPU 解码现有参考和成片，不连接 MCP、不产生新渲染、不修改 state、result 或旧模型回答。
输入 SHA 全部检查后，在 `artifacts/editing_observation_v1/` 追加带新编号的报告，保留之前的报告。

FFmpeg `scdet` 记录原生 PTS、时间基、图像变化分数、阈值及文件 SHA；每帧日志单独保存。
EDL 人为拼接点无论是否被图像检测器发现都会保存；检测候选再标注与 EDL 接缝邻近或在素材范围内部。
素材内部变化仍可能是闪光或文字变化，不能直接称为真实镜头。EDL 六个片段不等于六个镜头。

真实测量追加了两份报告：

| 检测阈值 | 参考候选 | 77 秒 round 0 候选 | 64 秒 round 1 候选 |
| --- | ---: | ---: | ---: |
| 10%（report_001） | 2 | 0 | 0 |
| 3%（report_002） | 22 | 22 | 12 |

10% 在这批画面上过于严格；降低阈值也会引入误检，因此 3% 只作为新协议的敏感导航设置。
两版成片另外有 5 和 2 个 EDL 拼接点。不能用候选数量比较剪法好坏或宣称检测召回率。
上述测量前后，135 个 state/result/call JSON 的 SHA 一致，旧成片 SHA 也保持一致。

当前运行已用完 16/16 个精看窗口和 2/2 次渲染，43/80 次请求中含永久保留的 uncertain 004。
本次没有重新调用真实 GLM、没有新的电影成片，也未重放未知输入。
在官方连接保持停止的情况下再次恢复原任务，仍为 43 次请求，选中 SHA `e6d10d90…55b4111`，原 state/result/request/response 字节均未改变。

`.venv-library` 全量回归 **366 passed、2 skipped**；跳过的两个模块缺少冻结发现线的
`browser_use/requests`，在原 `.venv` 单独验证这两个模块 **28 passed**，不把两组数量相加冒充新总数。
定格、源声静音、参考音轨持续、中文字幕的字形／描边／时间、安全文本、字体与媒体 SHA、
原生 PTS、EDL 接缝、模型字段修复和缓存恢复均有实际合成媒体或协议测试。
v2 入口通过完整合成闭环和恢复，缺少剪法绑定时仅修复一次并增加一次请求计数。
完成的旧任务拒绝直接升级且不改旧记录；剩余请求预算很少时仍可恢复已有完整结果。
