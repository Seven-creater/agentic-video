# 创作路线修复说明（2026-10-27）

适用于 `omni-server start --creative-audio`（粗剪+配音 → 声画审核 → 精剪）。基线是冻结的生产版本 `aa47a93_final_visual`。旧执行通道的行为保持不变，线上 `current` 版本未改动。

## 参考理解（10-25，评测阶段）
- 先像普通观众一样说出视频想表达什么，再写主旨、价值判断和标注过的文化常识；支持多条参考汇总。
- 立场写成列表以外的词时，归入"其他"，不判失败。

## 模型回复校验（10-26 ~ 10-27）
- **配音文稿**：提示词里的 `audio_mode=silent` 只表示不用原声，新配音文稿 `audio_draft` 不能省略。
- **时间规范化**：只在创作路线开启。模型描述"本次发送媒体自身时间轴"的区间，统一截到媒体实际时长，截空的删除，并记录在 `normalization`。剪辑点、字幕、配音锚点等决定类字段仍然严格校验。规范化只放宽，不新增任何失败条件。
- **精确报错**：所有通道的数值和越界错误都附带 `violation`（字段路径、值、允许范围）。修正请求里列出全部问题，最多 30 项。
- **格式修正**：创作路线的 opencode 和 chain 两个通道最多修正两次（原调用 → `_repair` → `_repair2`），其他通道仍只修正一次。结果未知的调用仍然一律不重发。
- **服务端错误重试**：智谱接口明确返回 500/502/503/504 时，等 60 秒重试一次；超时、断网等结果未知的情况仍不重发。

## 精剪（10-27）
- 精剪规划检查相邻段落是否连贯：时间或场景跳变时必须有衔接线索；没有铺垫的孤立段删除；删段时，挂在该段上的台词删除或改挂到相邻段落。
- 修订阶段兜底：以原计划渲染输出区间为准，与审核问题区间重叠的段落可修改入出点/操作或整段删除；问题区间之间不超过1秒的空隙也算作问题区间；问题区间之外的段落源范围和操作不变、不得删除。保留段的编号、相对顺序和contribution_to不变。
- 对白说话人检查提前到精剪规划和修订阶段，可以修正；交付前原有的那次检查保留，作为最后一道保险。

## 重跑与复用（10-27）
- `--reuse-plan` 可以沿任务链一路追溯到最初收到的规划，每一层都校验文件是否被改动。
- 配音复用：在上级任务链中找到完全相同绑定、且已收到的 TTS，就直接复用，不再付费。复用的配音单独计为 `reused`，不算作本任务的付费请求。上级任务中结果未知的配音仍会被拦截。

## 已知局限
- 复用的配音依赖上级任务的文件可读、且未被改动。
- 审核问题区间的端点恰好落在段落分界时，按半开区间处理。
- 内容和素材不匹配的情况（例如狂飙吃鱼缺少对应画面）不属于格式问题，靠审核如实判定。
