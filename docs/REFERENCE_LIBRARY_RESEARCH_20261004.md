# 固定参考、大电影库与按需剪辑：端到端调研

日期：2026-10-04，Asia/Shanghai。范围：任务巩固、文献核查、现有工程只读审计及后续验证建议。本轮没有调用创作模型、运行 ASR/FlashVID、下载电影、生成媒体或实现新管线。

## 1. 先固定任务，避免方向漂移

以 [任务约定](REFERENCE_LIBRARY_SPEC.md) 为准：**参考视频先确定主旨和剪辑目标，从远大于参考的素材库中找片段，素材反馈决定具体段落和人物路线。** 不再根据当前素材库选容易完成的参考，也不复制参考的固定故事结构。

单次任务的参考、库版本、目标和预算需要固定。参考分析如因新的原片证据而修正，应保留解释版本和理由；不能为了让现有素材合格而悄悄改主旨。

本轮信息分为四类：

| 类型 | 含义 |
| --- | --- |
| 用户已确认 | 参考优先、同主旨、人物连续、段落自由、按需精看、全自动创作、旧生成线冻结 |
| 文献已支持 | 某项机制或某个基准中的结果，不等于我们整条链已验证 |
| 现有工程事实 | 当前代码与本地历史报告能够直接核查的行为 |
| 本项目建议 | 下文提出的索引、循环、评估和原型方案，需要实测 |

## 2. 更接近目标的相关工作与边界

下表均核查了一手论文、会议页面或作者所属机构页面。2026 年工作按当前公开版本描述，不将预印本说成已被主会接受。

| 工作 | 可借鉴的机制 | 不能扩大的结论 |
| --- | --- | --- |
| [MovieGraphs，CVPR 2018](https://openaccess.thecvf.com/content_cvpr_2018/html/Vicol_MovieGraphs_Towards_Understanding_CVPR_2018_paper.html) | 人物、属性、互动、关系、原因与时间的图结构 | 包含人工标注和推断；不证明自动建图或自动成片的主旨正确 |
| [MovieNet，ECCV 2020](https://www.ecva.net/papers/eccv_2020/papers_ECCV/html/2710_ECCV_2020_paper.php) | 不同粒度的角色、场景、动作和镜头风格组织 | 数据集标注质量不是我们的模型自动索引质量；动画泛化另测 |
| [Movie101，ACL 2023](https://aclanthology.org/2023.acl-long.257/) | 中文角色感知描述、全局粗定位到局部精定位 | 定位单段不保证多段组成叙事；召回更多候选不保证首选更好 |
| [VideoAgent，2024，2403.11481](https://arxiv.org/abs/2403.11481) | 时间事件记忆与对象记忆分开，检索后局部观看核实 | 通用对象 re-ID 不等于可靠动画角色系统；不是成片评估 |
| [DrVideo，CVPR 2025，预印本 2024](https://arxiv.org/abs/2406.12846) | 粗文本记忆、任务缺项驱动的信息增补 | 问答表现不证明切点、连续性或主旨表达；粗记忆也可能漏事件 |
| [VideoTree，CVPR 2025，预印本 2024](https://arxiv.org/abs/2405.19209) | 查询相关性驱动聚类与观察深度 | 代表帧可能漏短暂关键动作；视觉相似不等于叙事作用相同 |
| [FlashVID，ICLR 2026](https://arxiv.org/abs/2602.08024) | ADTS 与 TSTM 处理视频视觉 token 的时空冗余 | QA 压缩结果不等于 0.10 保留率下人物事件、切点和剪辑无损 |
| [Automatic Non-Linear Video Editing Transfer，2021](https://arxiv.org/html/2105.06988v1) | 从参考提取视觉和时间风格，匹配库内镜头后迁移 | 精确速度仍需人工标注；不检验同主旨及长叙事。机构记录名称为 Automatic Style Transfer，属于 [CVPR 2021 AICCW Workshop](https://research.google/pubs/automatic-style-transfer-for-non-linear-video-editing/)，不是主会 |
| [DIRECT，2026 预印本](https://arxiv.org/html/2604.04875v1) | 素材、音乐与文字指令驱动全局规划；段落意图、候选反馈、连续性和声画指标 | 不是异源参考主旨及剪法联合迁移的完整验证；素材缺失、查询和特征误差仍存在 |
| [CutClaw，2026 预印本](https://arxiv.org/html/2603.29664v1) | 长电影/VLOG 与音乐、指令；角色或叙事中心剪辑；Editor/Reviewer 反馈 | 指令符合、节奏对齐不等于陌生观众理解目标关系 |
| [BEAT，2026 预印本 v2](https://arxiv.org/html/2605.27067v2) | 音乐驱动电影预告的弹性镜头时长 | v2 明确不同指标不统一改善，相关 critic/evaluator 可能强化评分偏好；不能保证动画泛化 |
| [MEDit-Bench，2026 预印本](https://arxiv.org/html/2607.25300v1) | 同素材多主旨、同主旨多专业编辑版本，评测画面传达的主旨 | 7–18 分钟素材、只裁切且忽略音频；不是小时电影的参考剪法迁移评测 |
| [VEBench，2026 预印本 v2](https://arxiv.org/html/2605.03276v2) | 剪法识别与多视频候选选择/时间定位分开评估 | 选择题及单次插片任务不是完整自主新片；懂手法不等于执行手法 |

VideoAgent 另有 Wang 等人的 [2403.10517](https://arxiv.org/abs/2403.10517)，与上表的 memory-augmented 工作不同，后续引用不可混淆。

**新颖性边界：** 参考驱动的剪法迁移已有研究，主旨驱动剪辑也已有基准。我们需要验证的是：异源参考的表达目标如何约束小时级素材库检索与段落重构，以及按需观察在实际成片质量和成本之间的作用。组合 agent、接 API、得到一个可播放视频，本身不足以证明研究贡献。

## 3. 改进后的端到端结构

不需要先完整写剧本，也不需要先逐角色精看整部电影。可以先有便宜、任务无关的目录，再由固定参考提出检索和观察需求。

```text
固定参考 → 观察主旨、关键证据和剪辑方法
          → 暂定表达需求与 slots（允许未填、允许修改）
          → 查询大素材库轻量索引，获取多条角色/事件候选
          → 针对缺项精看连续原片及上下文
          → 用实际证据更新记忆、比较完整角色路线、重构 slots
          ↺ 缺事件/转折/衔接就再检索；身份或时间不明就核验
          → 精确源定位与声音计划 → 结构化编辑表 → 实际渲染
          → 先盲看成片，再对照参考；失败按缺项返回上游
          → 实际成片、来源时间表、保留局限及成本
```

参考不作为失败循环的自由变量。素材不足可以形成有限制候选或任务失败，不能换参考掩盖不可完成条件。

### 3.1 参考目标保存什么

建议保存一份贯穿下游的参考记录：

- 主旨解释及原片支持区间：观众应理解的处境、行动、变化与关系；不强制所有参考都符合同一因果模板。
- 可见动作、对白/文字声称、外部信息与解释分开；字幕说“努力成功”不等于画面已显示努力导致结果。
- 必须保留的表达关系、允许变化的具体剧情、当前不确定之处。
- 剪法的形式、作用、声音依赖、支持区间和实施条件。观察不到的速度参数、切点、动机记为未知。
- 原参考 SHA、版本，以及需要局部复看的具体问题。

这是一种本项目协议建议，不是某篇论文的标准主旨标签集。

### 3.2 索引保存什么，哪些信息延后再看

| 层次 | 最小长期记录 | 按任务补充的内容 |
| --- | --- | --- |
| 媒体与物理区间 | 文件 SHA、版本、时间基、镜头/场景区间、代理映射 | 精确动作边界、源声音窗口与裁切余量 |
| 人物候选 | 带影片命名空间的角色 ID、外形证据、身份不确定性 | 变身/年龄阶段、当前伤势、道具、衣着和关系 |
| 共享事件 | 参与者及行动者/对象/见证者、可见行动与结果、原区间 | 事件前提、谁看到结果、理解需要的邻近事件 |
| 观察证据 | 来自画面/ASR/资料、采样方式、已看范围、粗看/精看状态 | 冲突证据、核验结论、关键证据完整性 |
| 本次任务 | 不写入永久事实层 | 可服务的 slot、观众理解、上下文依赖、候选优劣、缺项 |

不同电影的相似外形不能自动并成同一个角色。声纹或 ASR 说话人编号也不能直接当可见人物身份。对同一共享事件的不同角色视角，应保留角色作用而不是复制多个事件真值。

“某个微笑表示认可”只能是本次组合中的解释候选。长期索引主要记笑容、参与者、邻近行动和声音，避免第一次任务污染后续所有参考。

## 4. 端到端风险、应对与验证

下列应对是基于文献和代码审计的工程建议，均尚未在本项目电影路线实测。

| 编号 / 环节 | 可能失败的方式 | 建议应对 | 要验证的结果 |
| --- | --- | --- | --- |
| R01 参考理解 | 把“成功”这种宽泛词当作主旨，或凭字幕/常识补出不存在的因果 | 以原片证据形成表达关系；比较合理解释，保存未知；目标确定后版本化 | 不看解释的审阅者能复述目标；证据支持范围是否被夸大 |
| R02 异源与泄露 | 参考标题不同但重用同一电影；评审靠熟悉电影脑补 | 作品来源与局部画面复用检查；记录不明来源；评测分层记录观众电影熟悉度 | 来源一致性与局部重用漏检；陌生观众也能看懂 |
| R03 粗索引遗漏 | 压缩/稀疏采样漏掉关键动作，此后永远不精看它 | 文字、视觉、ASR 和邻近事件交叉召回；预留探索预算；未命中不当不存在 | 不同保留率与帧密度下的事件 Recall@K、关键事件遗漏和精看成本 |
| R04 错误知识入库 | 电影常识、粗看猜测变成确定事实，多模型不断引用放大 | 事实/推断/外部知识分层，记录证据与覆盖范围，允许撤回错误注释 | 哪些选片决定仅靠未知或外部知识；错误修正是否同步到关联候选 |
| R05 角色与状态 | 同一人物名字正确，但年龄、变身、伤势、道具前后冲突 | 身份与阶段状态分开；跨段相容性检查；关键身份选用前精看 | 误合并/误拆分及实际成片状态矛盾；有意时间跳跃是否可理解 |
| R06 事件边界 | 单镜太短缺因果，多分钟场景太长难检索；动作与结果被拆开 | 镜头/场景物理层与共享事件语义层分开；候选含邻近上下文与出入余量 | 扩大窗口后判断是否改变；选片是否保留必要的动作与结果 |
| R07 检索方向 | A 救 B、A 被救、旁观者画面都命中“救人” | 检索参与者作用、前后状态及目标关系；局部核验实际动作 | 角色互换、动作反转、表情相似但作用不同的困难负例 |
| R08 多段组合 | 各 slot 独立 top-1 很相关，合起来没有共同人物或转折 | 同时比较完整人物路线；保存候选进入/退出状态及依赖；拆分合并重排 slots | 相同候选池下，独立 top-1 与序列相容规划的成片理解差异 |
| R09 规划不可实现 | 先写具体剧情再找不到素材，或者只拿胜利表情声称解决了困难 | slot 写表达需求与必需证据；未满足保持缺口；通过实际候选改剧情实现 | 选入事件有原片证据；重构是否保留主旨而非弱化目标 |
| R10 源时间与切点 | 把抽帧播放时间、粗模型秒数、代理帧号当原片时间 | 显式源 PTS/时间基、窗口偏移、采样映射；连续原片精定位；裁后验证 | 原片→代理→入出点→成片映射；动作完成与实际边界误差 |
| R11 手法与能力 | 复制时长/快切牺牲叙事；模型声明有 J/L cut、match cut，程序却没执行 | 形式与表达作用分别存证；能力表匹配；不支持方法记缺口，候选方案偏差明确 | 实际镜头与声音关系是否支持方法声明；主旨和风格分别评价 |
| R12 音频 | ASR 有文本，但声音被删除；对白断句、说话人错配、音乐遮对白 | 原音轨独立时间轴；ASR 带对齐与不确定项；声音事件/音乐结构另测；实际混音审核 | 台词完整性、音画同步、J/L cut、音乐卡点；有声/无声分项评价 |
| R13 画幅与素材质量 | 横屏硬裁竖屏丢人物/道具，运动匹配造成奇怪缩放，动画闪光被误判切镜 | 关键证据区域与构图约束；裁切/留边由模型选择；边界候选核验 | 原画与输出的证据可见性、质量、角色/道具保留；镜头检测误差 |
| R14 观看与解码成本 | 反复全看电影、重复发送长上下文、每镜从全片重解码 | 小窗口缓存绑定原片 SHA 与映射；复用事件记忆；只对会改变决策的缺项增补观察 | 首次建库与后续增量成本、重复观看率、缓存前后一致性及实际耗时 |
| R15 循环与恢复 | 反复改查询没有新信息；重开目录重置预算；缓存源/策略已变 | 持久化任务预算、slot 版本、已看范围、否定证据和请求身份；阶段预留渲染/审阅资源 | 重启不重放不明请求；成本不归零；停止有原因，最佳有效候选可恢复 |
| R16 评审与指标 | 作者解释提示答案；高召回/高节拍/高重叠即被当作好故事 | 内部反馈与最终评估分开；先视频盲读，再主旨/剪法对照；匿名、交换顺序、独立人评 | 陌生观众理解、人物连续、切点、风格与成本分项；模型判断与人评一致性 |
| R17 素材确实不足 | 把“尚未找到”直接判不可实现，或换参考/编事件掩盖不足 | 扩范围与核验后报告检查覆盖；保留表达缺口；标明候选局限或未完成 | 检索失败与库不支持分别分析；技术有效不冒充语义成功 |
| R18 建库与摊销 | 参考很少，首次建库占大头，却只报告后续便宜调用；过早精标全部角色 | 先最小可检索目录，精看随任务增补；对首次任务与重复使用分别计算 | 首次任务总成本、后续单次增量、不同参考数量下累计质量/成本；不得隐藏建库成本 |

R02 可借 [TransVCL，AAAI 2023](https://ojs.aaai.org/index.php/AAAI/article/view/25158) 的局部复用定位思路，但标题或相似度阈值不能单独保证异源。R03–R08 的记忆/定位依据见 MovieGraphs、Movie101、VideoAgent、DrVideo、VideoTree；跨段组合仍是待验证设计。

R10 要考虑 FFmpeg 的帧率重采样会丢帧或重复帧，不能把归一到 24 fps 的帧号直接当原片帧号。见 [FFmpeg fps](https://ffmpeg.org/ffmpeg-filters.html#fps) 与 [trim](https://ffmpeg.org/ffmpeg-filters.html#trim)。[PySceneDetect](https://www.scenedetect.com/docs/latest/) 或 [TransNet V2](https://arxiv.org/abs/2008.04838) 可提出镜头边界候选；镜头变化不等于语义事件变化，更不是完整事件标注。

R12 可借 [WhisperX](https://arxiv.org/abs/2303.00747) 的 VAD 与强制对齐思路。具体中文小模型待实测；ASR 是语言证据，音乐节拍可用 [librosa beat tracker](https://librosa.org/doc/main/api/generated/librosa.beat.beat_track.html) 等工具提供候选位置。这些时间特征不自动决定哪里应该切镜，叙事判断仍归模型。

## 5. 必须新增的失败意识

**有限电影库不保证支持任意参考。** “同主旨”和“同剪法”分别可能失败：素材能表达目标却缺匹配动作，或快切做得很像却讲不出内容。禁止用一个总分隐藏这种区别。

最小结果记录建议分别写：

- 技术：有效源文件、合法范围、可播放渲染、来源可追溯。
- 表达：参考主旨确定程度、关键证据覆盖、实际成片盲读、仍未成立的关系。
- 连续性：人物身份、状态、事件衔接与有意跨时段安排。
- 剪法：实现、部分实现、不支持和待核验，分别绑定实际成片时间。
- 成本：初次建库、任务精看、文本推理、音频处理、解码渲染、缓存与重启恢复。

最佳有限制候选可以作为交付物，但成功标记不能由“FFmpeg 返回 0”“JSON 合法”或模型一句 accept 自动生成。对未知信息不伪造百分比置信度，更不把多个模型意见一致当成真实证据。

## 6. 当前仓库的复用点和真实缺口

本节是源码事实，非未来实现承诺。审计版本 HEAD 为 `8d60ea9`；本轮只改文档。

| 现有位置 | 能复用 | 新路线还缺什么 |
| --- | --- | --- |
| `omni_story/pipeline.py` 的 `analyze_reference`；`reference.py` 的 `build_transfer` | 事实/解释区分、参考局部复看、同一来源记录贯穿下游 | 参考不确定性与新任务状态仍需扩展 |
| `omni_story/donor_prompts.py`、`prompts.py` | 旧提示词作为有来源的历史保留 | 当前先设计可生成剧情；不适合作为素材库 slot/检索协议，需独立新协议 |
| `omni_story/production.py` 的 `edit_sources` | 观察实际媒体后决定编辑，有限预算与原始响应 | 当前按短素材逐条全看；缺长期电影目录、查询、角色事件记忆和按需窗口 |
| `omni_story/editing.py` 的 `compile_plan`、`render` | 实际源范围验证、SHA、结构化编辑表和 FFmpeg | 当前最多 32 行/180 秒、重复区间一律拒绝、效果有限；这些是旧工程限制，不是所有剪辑的理论约束 |
| `omni_story/editing.py` 的 `render`、`mux_music` | 渲染与参考音乐处理 | `-an` 去除素材原声；目前没有原对白混音、J/L cut 或独立音效轨道 |
| `production.py` 的成片 `FINAL_REVIEW` | 模型实际看过渲染候选 | 当前同时提供剧本/参考/映射，存在答案提示；`pipeline.BLIND` 是文字剧本盲读，不能称成片视频盲审 |
| `production.py`、`discovery/state.py` 的预算/缓存/锁 | 请求身份、预算、来源核验和不重放保障 | 缺电影索引更新与任务级检索循环恢复边界 |

现有每个切片重复校验大源 SHA、从电影输入处理切片，搬到小时级库会增加耗时；应评测窗口缓存与原片寻址，不能只统计 API token。

本轮未改变这些代码、旧提示词、冻结发现配置或历史运行。

## 8. 验证顺序：先证明能检索并组成，再扩工程

这些是后续建议，本轮不执行，也不预设成功。

### 8.1 最小真实闭环

固定一条异源参考和一部完整电影。电影可以有轻量粗目录，但不能由人工告诉模型用哪些片段。按缺项精看、自由重构 slots，交付实际可播放视频及下列证据：

- 原参考与电影版本/SHA、异源核查状态。
- 参考的主旨/剪法证据；slot 每次修改与原因。
- 每个选片的原时间、人物与状态证据、上下文依赖。
- 编辑表、实际输出时间、音频处理、边界验证。
- 先盲看实际成片的理解记录，再对照主旨与剪法。
- 未满足要求、失败类型、实际观看/调用/解码成本。

技术单元可先用小样验证时间映射和音频处理；整条研究验收仍需完整电影库，不拿短片小样代替小时级检索。

### 8.2 在同等预算下比较机制

1. **需求驱动观看：** 同一粗索引，比较固定窗口精看与缺项驱动精看；固定最大预算，并额外报告实际用量。
2. **段落可变性：** 同一参考和候选池，比较固定参考 slots 与素材反馈下重构 slots；主旨不能作为可变项。
3. **组合规划：** 同一候选池，比较各 slot 独立 top-1 与考虑人物/状态/事件依赖的序列选择。
4. **粗看压缩：** 固定相同采样帧，比较视觉保留率 1.00、0.25、0.10，分开记录角色事件召回与耗时；再做固定总观察成本下的比较。帧密度与 token 压缩不是同一个实验变量。
5. **评审可信度：** 对实际视频隐藏创作解释、匿名方法并交换候选顺序；模型评价与独立人评分别报告。人评不参与运行时创作。

首次建库与后续参考增量成本分开。不同方法不得使用不同可见标注、不同库版本或额外看过的关键片段作为隐含优势。记录缓存冷/热、GPU 时间、token、观察过的原片区间和实际耗时。

参考远少于素材，并不自动保证重型索引值得建立。总成本按 `首次建库成本 + 各参考任务增量之和` 报告；一个参考时的冷启动与多个参考复用同一电影库时的摊销分别比较。精看覆盖随查询增加，不把“所有人物都已经完整看过”作为启动前提。

研究阶段增加多条固定参考、多部电影及难负例；不只挑容易完成的任务。不支持的主旨、依赖对白才能成立的参考、变身人物和同外形不同角色也应有明确失败分析。

### 8.3 不把单一指标当成成片质量

| 层次 | 建议测什么 | 单独不足之处 |
| --- | --- | --- |
| 检索 | 关键事件 Recall@K、角色作用准确性、必要上下文覆盖 | 相关片段未必能组成故事 |
| 定位 | 动作/镜头边界误差、事件完整性、真实渲染检查 | tIoU 相近仍可能截掉关键瞬间 |
| 连续性 | 身份、状态、道具和事件衔接错误；有意跨时段可理解性 | 同一人出现不等于叙事成立 |
| 主旨 | 陌生观众自由复述与目标关系对照；静音、有声分别测 | 作者解释或背景常识可能掩盖画面缺口 |
| 剪法 | 实际技术识别、时间/动作/音频证据及方法相似度 | 节拍命中或剪辑表行数不代表参考风格 |
| 成本 | 首次建库、每参考增量、模型/音频/解码/渲染成本 | 低 token 不等于低总耗时或高质量 |

MEDit-Bench 的 §3.5 与 §6 指出时间重叠评估及 LLM judge 的边界，包括明显位置偏置；其集合式时间指标不能独自评价重排后的故事顺序。BEAT v2 也说明 critic 与 evaluator 的相关判断可能影响得分。这支持分项评估与独立人评，不支持直接将某个模型评分作为成功真值。

## 9. 后续工程顺序建议

先完成媒体来源、原时间映射、轻量目录和任务预算/证据记录，再验证查询→连续窗口→候选核验。随后接入可修改 slots 与完整人物路线比较，最后补声音时间轴、有限剪法能力、实际成片盲审和实验对照。

不先开发“所有角色的完美全片索引”、大规模多 agent 分工或无限制重剪；这些规模选择应由上述瓶颈实测推动。当前没有为新路线冻结具体模型、参数、预算或接口，也没有改变旧冻结程序。
