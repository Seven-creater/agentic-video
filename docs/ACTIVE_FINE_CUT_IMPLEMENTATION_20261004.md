# GLM 主动精剪：实现与下一轮提案

本轮把通用精剪决策接入电影素材库执行链，允许 GLM 主动省略过程、选择不连续关键瞬间、
改变播放速度和保留必要停留，即使某项技巧没有在参考中被可靠识别。
本轮没有新增真实模型请求或电影成片；工程测试使用合成媒体和预先构造的模型回答。

## 本轮实现

新增前向协议 `active_fine_cut_v1`，入口为 `--active-finecut`，包含已有 semantic-audit 和 editing-v2。
它只用于尚未提交计划、尚无渲染的任务；启用后写入不可更换的手册快照及 SHA，恢复不依赖再次传入开关。
已有任务不能用它重新解释付费计划或追加渲染，固定真实任务也不能直接使用该开关重跑。

实际顺序为：

1. GLM 按参考目标和已完成素材观察形成草案 EDL。
2. GLM 读取通用[主动精剪手册](../omni_story/library/craft_knowledge/ACTIVE_FINE_CUT.md)，提交完整精剪 EDL。
   同时说明每段新增信息、入出点、速度和停留理由，逐项交代草案片段去留和原表达义务的覆盖。
3. 执行器对最终短区间重新制作原片代理；独立事实观察看不到计划、参考主旨或待验证动作答案。
   另一次调用核对说法；源 SHA、原时间、观察内容 SHA 与目标片段绑定。
4. 原草案的每条 slot 表达要求以稳定 claim ID、原文及最终片段映射加入实际输出审核。
   重划 slot 不能让旧要求从审核清单消失；模型自行声称 preserved 也不等于已经成立。
5. FFmpeg 执行模型选定的不连续精切、0.5–2 恒定倍速及真实尾帧停留。先对实际成片做静音盲读，
   再独立审核重复、等待和无新增信息的片段；冗余审核不提供草案、精剪理由或参考解释。
6. 另行将实际画面与参考目标、全部精切事实和原表达要求比较。未支持的事实、未解决矛盾、
   必须依赖文字、未保留的信息或冗余均阻止整体通过。
7. 若预算支持第二轮，反馈缺项后由 GLM 重规划；候选比较优先选择同时通过语义和精炼审核的版本。
   无联合通过候选时，选择结果必须保留局限，不能把有效媒体存在等同于质量通过。

片段映射是全片审核上下文，校验器不能证明其语义正确。独立观察、盲读和审阅仍可能出错，
最终状态不是陌生观众真值。没有因为手册使用了“精剪”就保证 GLM 已具备专业剪辑水平。

## 保持的边界

- 通用手册没有本条参考的人物、剧情、秒数或正确剪法；Codex 没有代选真实电影切片。
- `general_optimization` 与 `reference_transfer` 分开记录；前者不能冒充已经识别并迁移参考方法。
- 不固定镜头必须几秒，不强迫加速、慢放或定格。短片段可能缺信息，长片段也可能是必要停留。
- 速度指输出恒速参数；不宣称实现平滑速度坡道、光流慢动作，或测出了参考的准确原始倍率。
- 当前官方视觉 MCP 未进行音频听审；画面叙事与音乐节奏分别记录，ASR 不证明音乐卡点。
- 仍是 GLM-5.3-Flash 官方视觉 MCP，由 Codex 会话连接；没有换标准 API、租服务器或启用 FlashVID。
- 旧 MiniMax 与抖音发现路线继续冻结；不重放结果不明的 004、不清除旧评价、不换目录重置预算。

## 预算与恢复

每轮在提交草案前保存最终片段上限。预留公式为 **`12 + 4N` 次请求**：
草案、精剪、静音盲读、精炼审核、目标审核、候选选择六个阶段各预留原请求和一次格式修复；
每个最终短区间另预留独立事实观察与说法核对，各允许一次修复。即使单候选不需调用选择，
仍先保守预留。失败和格式修复计入预算；未明提交不自动重放。

搜索也必须先保留后续完整审核所需额度。首次预算分配写入任务记录；恢复时不能因余额下降
反向缩小已提交计划的片段上限。合成媒体测试验证再次执行返回原结果，无新请求、无新渲染。

本轮新增 `--prepare-active-finecut`：仅在已有任务追加 CPU 提案，不启动 MCP、不启用新协议、不授权费用。

```powershell
.\.venv-library\Scripts\python.exe -m omni_story.library --reference data/ref/video.mp4 --library data/videos --output runs/library_reference_20261004 --prepare-active-finecut
```

固定任务已实测为 **79/80 次请求、16/16 个唯一精看窗口、4 次渲染**，仅余一次请求。
同目录提案 `artifacts/active_finecut_preflight_001.json` 为：

| 项目 | 上限 |
| --- | --- |
| 接下来新增模型请求，含每阶段一次格式修复 | 44 |
| 最终精切片段 | 8 |
| 新电影成片渲染 | 1 |
| 新的唯一电影精看窗口 | 0 |

44 次是完整流程的保守预留，不是预测实际消耗。计划与所有新增短片段只使用已完成精看且有实际原件绑定的范围，
但最终短片段仍需独立读取。原电影文件、输入锁和历史调用继续保留；不会把旧失败升级成通过。
若用户批准，须单独实现／记录同目录增量预算与一次渲染授权，保留原 80 次基线和全部 79 条调用。
从当前账本起最多新增 44 次，即累计上限 123；不能把 80+44 误写成允许新增 45 次。
目前没有激活这个扩展执行器；不能直接改 state 的 max_requests、复制任务或使用新目录运行。
旧授权和 reference-craft 的固定阶段校验也必须保留，不能为运行新阶段删除它们。

## 本地证据

当前新增纯协议测试 74 项通过；精剪执行、语义门与入口相关测试 63 项通过。
其中合成媒体实际经过生产文件队列、FFprobe、FFmpeg、范围与事实校验和恢复：
一个草案范围被拆成两个不连续区间，分别 2 倍和 0.5 倍播放，最后保留 0.2 秒真实尾帧；
实际帧量化后的输出约 1.466667 秒。模型回答是测试夹具，这个长度不是对真实故事的建议。
测试覆盖一次格式修复、冗余导致有限结果，以及重划 slot 后原表达要求 unsupported 阻止通过。
本轮最终全量回归 **612 passed、2 skipped**（526.09 秒）；跳过的是缺少 browser_use/requests 的冻结发现线模块。
这些工程测试不证明 GLM 在真实电影上的剪辑质量。

wheel 实测包含全部 11 个知识资源。前一轮 10 文件知识快照 SHA 仍为
`4422c3554955a064cf024a3e198c4f590cf281cae738b120a624eaa535169e4f`，没有追溯改变旧 GLM 输入。

关闭模型连接后，两个旧恢复入口和 CPU 提案再次执行均保持 79 次请求、4 次渲染，
420 个受保护文件及旧调用账本通过校验。单独证据在
`artifacts/active_finecut_preflight_verification_001.json`；没有新的真实质量评分。

旧 `render_3/final.mp4` 仍为 34 秒，其 SHA 为
`d49da8831b975fc655ad96eb7453311fa7c3e4d7ae68b54207d89ed643c77190`；

`e2406bad6ee489a126b4436ab1e375dd0fa5be996f5dbf3a0ab914336d8d31a2`。
该结果仍是终审协议失败、语义门未通过的候选，本轮代码不能把它变成新的通过版本。

## 后续用户澄清与未激活的同目录执行器

用户随后明确重新剪辑应重新发起新调用，并要求取消80次内部总上限，停滞时停止。
这取代前述44次预算提案；旧提案、输入锁和调用历史不删除，不被冒称套餐限额。
新增 `extension_budget.py` 与 `finecut_continuation.py` 提供同目录一次增量工作流，保留原账本头部，
运行时无数字总请求cap，本轮单独统计。阶段有序前进、同名不重复提交、每次格式失败最多修复一次，
新未知或在途提交阻止继续，原不明004不能重放。最多32个片段是现有EDL结构约束，不是额度。

`--continue-finecut` 缺少单独记录的任务授权时在任何模型调用／渲染前拒绝；现阶段没有激活它。
新执行器使用既有canonical参考和单独hash-bound craft观察补充，未转换craft方法为旧索引或人工答案；
全部最终切片重新观察，精剪、静音盲读、独立精炼审核和原表达义务门保留。旧阶段在冻结历史视图
上继续严格校验，新结果单独保存，原成片与评分不变。

用户进一步要求查清MCP额度和避免MCP的方法，并确认Max。当前先完成
[官方规则调研](GLM_MAX_QUOTA_AND_NATIVE_VIDEO_20261004.md)，没有新模型请求、真实增量授权或新电影渲染。
标准按量API和支持的Agent套餐原生视觉是不同路线，不静默替换本项目提供方。

追加执行器、无次数上限的进度状态与真实Node HTTP guard的合成检查 **71 passed**（353.81秒）；
此前关联旧reference-craft/revision/continuation/CLI检查 **66 passed**（213.91秒）。两组范围不同，
不能将它们与前向版本612项全量回归相加后称为新的全量回归。新增进度策略没有进行真实GLM运行。
